# Harbor 답변 표시와 장기 세션 개선 계획

작성·구현: 2026-10-24. 상태: 1.8.0의 계획 1·2·3을 1.8.1의 실제 SSH 복구, 1.8.2의 조판·행 배치 회귀 수정으로 보완. 검증 범위와 실제 서버·물리적 다중 모니터에서 추가 확인할 항목을 아래에 구분한다.

터미널에서 Claude와 Codex를 실행하는 현재 흐름을 유지하면서 답변을 읽기 쉽게 표시한다. 계획 1은 완성된 답변 블록의 수식·표 조판, 계획 2는 글꼴과 크기 조절, 계획 3은 장시간 원격 작업의 연결 진단과 세션 유지다.

## 계획 1 완성된 답변 블록 조판

### 사용자 동작

답변이 생성되는 동안에는 기존 CLI 텍스트를 표시하고, 블록이 완성되면 같은 세션 안에서 수식·표·제목·코드를 조판한 내용으로 교체한다. 별도 AI 대화로 전환하거나 답변을 다시 생성하지 않는다. 원문 보기로 되돌릴 수 있게 하며, 조판 실패 시에는 기존 텍스트를 유지한다.

[CC Intelligent UI](https://github.com/razorback16/cc-intelligent-ui)는 Claude의 `ui.render` 훅에서 완성된 답변 블록을 받아 Typst로 PNG를 만든 뒤 터미널에 표시한다. [내부 동작](https://github.com/razorback16/cc-intelligent-ui/blob/main/docs/how-it-works.md)과 [제약](https://github.com/razorback16/cc-intelligent-ui/blob/main/docs/limitations.md)을 참고한다. 현재 구현의 macOS/Linux 의존성, 지원 터미널, SSH에서의 선택·복사 제약 때문에 Harbor에 그대로 설치하는 것을 완료 조건으로 삼지 않는다.

### 구현 방식

1. Claude 2.1.287 이상의 공식 `ui.render`·`turn.step` API에 세션 전용 모드를 연결한다. 생성 중에는 네이티브 텍스트를 유지하고 실제 턴 스트림이 끝나면 `AssistantMessage`의 정식 Markdown을 인증 브리지로 보낸다. 출력이 잠깐 멈춘 시간을 완료로 추측하지 않는다.
2. 기존 Harbor의 Markdown·KaTeX·Mermaid 렌더러와 포함 글꼴로 실제 브라우저 DOM을 조판한다. 1.8.2에서 PNG 복제를 제거했다. 복제한 표의 너비·행 높이가 달라져 겹치던 문제를 CSS 우회로 계속 보정하지 않는다. Typst·별도 서버 브라우저 설치는 필요 없다.
3. 조판 높이를 Claude에 응답하면 네이티브 모드가 같은 자리에 행을 확보한다. `rows-v2`는 모든 행에 답변 ID와 행 번호를 연결해 첫 줄이 잘려도 현재 보이는 부분을 찾는다. 실제로 위치가 확인된 연속 행만 조판하여 입력·상태 행을 덮지 않는다. Kitty·iTerm 이미지 프로토콜은 사용하지 않는다.
4. 표시와 선택에 같은 DOM을 사용한다. 수식 복사는 정식 TeX 한 번, 표 복사는 탭·줄바꿈으로 제공하고 기존 번호 인용과 파일 링크를 유지한다. 문서 크기 변경으로 높이가 늘어도 이미 확보한 행 안에서 스크롤한다.
5. SSH에서는 기존 전용 역방향 인증 브리지로 원문과 배치 정보만 전달한다. 구버전 첫 줄 마커 요청은 추가 공백을 예약하지 않고 원문으로 돌아가며, 완료 답변을 접힌 조판 카드에 보관한다. 브리지·버전·화면·시간·크기 제한에서는 네이티브 원문을 유지한다. 원문 캐시는 개인 데이터 폴더에 보관한다.
6. Codex는 주 대화의 정확한 `item/completed`·`agentMessage`를 같은 표시 계층에 연결했다. 확인된 네이티브 화면 교체 훅이 없어 원본 TUI는 보존하고 같은 터미널 안에 접을 수 있는 **완료 답변 조판 보기**를 제공한다. 이는 Claude의 원래 위치 교체와 다른 방식이다.

### 검증과 한계

- 한글 설명, 분수·행렬·여러 줄 수식, 긴 표, 코드, 이미지를 같은 답변에서 표시한다.
- 생성 중 입력·승인·Ctrl+C·CLI 단축키는 기존 터미널에서 정상 동작한다. 조판 과정이 키 입력을 가로채거나 Enter를 자동 전송하지 않는다.
- 창 크기 변경·분할·별도 창·새로고침·재접속 후 블록 순서와 스크롤 위치를 유지한다.
- 로컬과 모의 SSH에서 선택·복사·인용·링크를 검증한다. 잘못된 수식과 조판 실패는 원문으로 복구한다.
- 조판은 백그라운드에서 처리하고 시간·메모리·이미지 크기를 제한한다. 늦은 결과가 다른 대화나 이미 닫힌 창을 덮어쓰지 않는다.

네이티브 Claude CLI·PowerShell/Bash 래퍼·인증 브리지·Electron 조판 경로는 격리한 HOME·포트와 로컬 모의 모델로 확인한다. 실제 사용자 대화에 테스트 입력이나 유료 추론을 보내지 않는다. 이전 CLI의 구버전 연결은 원문과 카드로 호환하며 새 실행부터 `rows-v2`를 사용한다. 기존 `TerminalPane.tsx`의 SIXEL·iTerm2 수신과 이번 조판은 별개다. Claude 모드의 지원 조건은 [공식 문서](https://code.claude.com/docs/en/plugins/mods)를 따른다. 답변은 128,000자·UTF-8 256KB, 행 예약은 최대 400행·8,192px 높이로 제한한다.

## 계획 2 한글 가독성과 크기 조절

상태: 구현·격리 검증 완료. 다음은 모든 사람의 최적값을 단정한 기준이 아니라, 사용자가 직접 바꿀 수 있는 시작 설정이다.

| 영역 | 적용한 기본값 | 조절 범위 |
| --- | --- | --- |
| 터미널 | D2Coding 일반형 1.4.0, 15px, 줄 간격 1.45 | 10~28px, 줄 간격 1~2배, 설치된 Cascadia Code·Consolas 선택 가능 |
| 문서와 조판 본문 | Pretendard 1.3.9, 16px, 줄 간격 1.7 | 12~28px, 줄 간격 1.2~2.2배 |
| 메뉴와 왼쪽 목록 | Pretendard, 기준 크기 14px | 12~18px; 제목·목록·보조 설명의 크기 차이를 유지하며 조절 |

[D2Coding](https://naver.github.io/d2-coding-font/)의 일반형·굵은 글꼴과 [Pretendard](https://github.com/orioncactus/pretendard)의 한글 전체 가변 글꼴을 앱에 포함한다. 프로그래밍 합자 빌드는 쓰지 않는다. 배포 파일은 수정하지 않은 고정 커밋의 원본이며 OFL 1.1 라이선스·저작권 고지·SHA-256을 [글꼴 출처](../public/fonts/README.md)에 남겼다. 시작할 때 외부 글꼴 CDN이나 시스템 글꼴 설치가 필요하지 않으며, 로딩 실패 시 명시한 한글·영문 대체 글꼴을 쓴다.

### 사용과 저장

오른쪽 위 **글꼴·읽기 설정**에서 터미널·문서·메뉴 설정을 독립적으로 바꾼다. 변경은 즉시 반영되고 `harbor.typography.v1`에 저장되며 같은 Harbor 주소를 사용하는 다른 창에도 동기화한다. **기본값 복원**은 세 영역을 위 기본값으로 되돌린다. 문서 창에서 사용하던 Ctrl+휠 확대 비율은 별도의 배율로 유지한다.

터미널 설정은 기존 xterm의 글꼴·크기·줄 간격 옵션을 갱신한 뒤 글꼴 로드 완료와 창 크기에 맞춰 재측정한다. 셸·AI 프로세스나 대화는 새로 만들지 않는다. 문서 크기를 바꾸는 동작과 메뉴 크기를 바꾸는 동작도 서로 영향을 주지 않는다.

### 확인한 범위

- 설정 파손·지원하지 않는 버전·범위를 벗어난 값·허용하지 않는 글꼴 이름을 검증하고, 버전 없는 이전 형식의 값은 개별 선택을 보존해 변환한다.
- 원본 글꼴 파일의 고정 SHA-256, D2Coding 일반·굵은 글꼴의 한글 2배 폭, 영문·숫자·박스 문자의 일정한 폭을 검사한다.
- 격리한 Electron에서 두 D2Coding 굵기와 Pretendard의 실제 로드를 확인하고, 크기 독립 조절·새로고침 저장·별도 창 동기화·기본값 복원을 검증했다. 외부 글꼴 요청은 발생하지 않았다.
- 1.8.2의 조판 본문은 앱에 포함된 글꼴로 실제 DOM을 표시한다. 표시와 선택의 글자 크기를 따로 복제하지 않으며 한글·분수·행렬·표·코드와 선택문을 같은 문서 흐름으로 처리한다.
- 초기 배율 검증은 1·1.25·1.5·1.75·2의 PNG 경로였으며, 긴 표와 네이티브 뷰포트의 첫 행이 사라지는 경우를 놓쳤다. 1.8.2는 실제 Electron DOM에서 긴 한국어 표와 후속 문장 간 경계, 첫 행 없는 예약 영역, 입력 행 보호, 요약 후 오래된 조판 제거와 크기 변경을 별도 회귀 테스트로 고정한다.
- 실제 배율이 다른 두 모니터 사이의 물리적 이동과 개인별 장시간 읽기 편안함은 사용 환경에서 추가 비교할 항목이다. 이를 집중력 문제나 모든 사용자의 최적 가독성으로 단정하지 않는다.

## 계획 3 장기 SSH 세션 유지와 연결 진단

**2026-10-26 수정(1.8.5):** 사용자의 PC는 절전되지 않는 조건이다. 원래 요구는 Harbor·SSH 연결의 안정성 조사와 수정이며 tmux 도입 요청이 아니었다. 자동 tmux 적용은 철회하고 새 터미널·기록 재개·연구실을 직접 SSH로 되돌렸다. 기존 유지 세션만 작업 보존을 위해 호환한다. 일반 SSH에서 원격 exit 없는 오류·close를 코드 0 종료로 취급하던 처리를 수정하고, 채널·connection 오류의 중복 정리와 허용된 오류 코드·이벤트 출처 진단을 추가했다. 실제 밤샘 끊김의 과거 원인은 아직 확인되지 않았으며 아래 tmux 구현은 1.8.0~1.8.4의 이력이다.

### 진단과 구현 범위

기존 버전은 15초 간격 keepalive와 최대 3회 연속 무응답 설정을 사용했지만 SSH 오류·close와 실제 원격 종료를 같은 처리로 연결했다. keepalive를 늘리는 것만으로 같은 프로세스를 복구할 수 없었고, 과거 밤사이 Compiler 종료의 원인을 확인할 기록도 없었다. 화면 전환 도구나 PC 절전을 원인으로 확정하지 않는다. 설정의 의미는 [ssh2 문서](https://github.com/mscdex/ssh2#client-methods)를 따른다.

현재 구현은 새 관리형 SSH 터미널에서 tmux·Bash를 감지하여 전용 tmux 세션 안에 셸을 한 번 시작한다. SSH가 끊겨도 이를 종료로 표시하지 않고 같은 세션으로 자동 재접속한다. 기존 일반 SSH 세션을 실행 중에 이동하지 않는다. tmux·Bash가 없거나 일반 OpenSSH 대체 연결을 사용하면 **일반 SSH · 연결 유지 미지원**과 설정 안내를 명시한다. 서버 도구를 설치한 뒤 새 터미널을 열어 유지 여부를 확인한다. 서버에 도구를 자동 설치하지 않는다.

- **연결과 종료 분리:** 연결 중·연결됨·재연결 중·연결 끊김·실제 종료를 구분한다. 끊긴 동안 입력을 보내거나 재연결 후 자동 재전송하지 않는다. 실제 pane 종료는 별도 exit code로 처리한다.
- **원래 프로세스 복구:** 자동 재연결은 기존 tmux 세션만 attach한다. 원격 세션 누락·서버 재부팅·인증 실패에서 CLI를 자동 새로 실행하지 않는다. 서버 대상 설정이 변경되면 이전 기록을 보존하고 연결을 보류한다.
- **Harbor 연결 복구:** 원래 역방향 포트와 MCP·훅 인증을 다시 사용한다. 포트 충돌이나 forwarding 거절에서 임의 포트로 바꾸지 않는다. 인증 정보와 Codex endpoint는 원격의 사용자 전용 tmux 환경에 보관하고 인증된 SSH로만 읽어 복구한다. 기존 CLI 프로세스나 대화 ID를 바꾸지 않는다.
- **앱 종료와 터미널 종료:** 앱 종료는 유지 SSH를 분리하고 개인 데이터에 복구 목록을 남긴다. 같은 설치·데이터로 다시 시작하면 복구한다. 터미널 탭·서버 목록의 X는 원격 유지 세션을 실제로 종료하며 실패 시 목록을 남긴다. 로컬·일반 SSH는 앱 종료 시 기존처럼 종료된다.
- **인용 유지:** 인용 원문·주석·출처·네이티브 대화 연결과 번호 상한을 별도 개인 데이터 파일로 저장한다. 앱 재시작 후 이전 `[#n annotation]`이 다른 선택문을 가리키지 않게 하며 다른 대화의 인용은 거부한다.
- **원인 기록:** 개인 진단에는 시각·터미널 ID·연결 상태·오류 분류·재시도 번호, 사용자 종료와 데스크톱 suspend/resume만 기록한다. 명령·답변·주소·인증 정보는 넣지 않는다. resume은 연결이 끊긴 유지 세션의 재연결을 즉시 시도한다.

연구실 스케줄러는 앱 재시작 후 일시정지로 복구한다. 기존 원격 프로세스가 살아 있다는 사실을 새 과제의 자동 재개 허가로 바꾸지 않는다. 앱이 꺼져 있는 동안 Harbor의 메시지·배정·훅 서비스는 제공하지 못하며 원래 연결을 확인한 뒤 계속한다.

### 검증과 남은 한계

격리된 실제 로컬 ssh2 전송과 모의 tmux 실행기에서 합성 작업 프로세스를 유지하고 전송 단절·백엔드 재시작 후 같은 PID·네이티브 대화 ID·고정 포트로 복구함을 확인했다. 실제 `AgentBridge` HTTP 라우터의 MCP·훅 인증과 원래 인용·주석을 확인했고 잘못된 토큰·다른 대화의 참조는 거부했다. 입력 중복 방지, 정상 종료 코드, forwarding 충돌, 원격 세션 누락, 명시적 종료 실패 시 목록 보존, 전원 복귀와 진단 필드 제한을 테스트한다. Git Bash에서는 초기 스크립트 구문과 토큰을 tmux argv에 노출하지 않는 임시 파일 정리를 검증했다.

**1.8.0 검증에는 실제 Linux tmux가 빠져 있었고 접속 회귀를 놓쳤다.** 1.8.1에서는 Compiler의 실제 tmux 3.6에서 별도 검증용 셸만 생성해 연결·단절·같은 PID로 자동 재접속·명시적 종료를 확인했다. 기존 사용자 터미널·대화에는 입력하지 않았다. 실제 밤샘과 과거 종료 원인은 여전히 확인하지 않았다. 모의 실행기의 성공을 실제 tmux 명령의 호환성 확인으로 대신하지 않는다.

tmux는 [분리 뒤 같은 프로세스에 다시 연결하는 도구](https://github.com/tmux/tmux)이며 서버 재부팅 후 프로세스 복구 기능은 아니다. 다른 PC·휴대폰이 같은 Harbor 세션에 접속하는 서비스도 이번 범위에 포함하지 않는다. tmux를 통과하는 모든 이미지 프로토콜이 지원된다고 가정하지 않으며 계획 1의 표시 계층은 별도로 검증한다. 사용법과 내부 복구 절차는 [사용자 안내](user-guide.md#장시간-ssh-작업-유지), [유지보수 안내](maintainer-guide.md#장기-ssh-세션과-연결-진단)를 따른다.

## 변경 범위

계획별로 소스 구현·격리 검증·설치본 반영과 실제 사용 중인 앱 재시작을 구분한다. 실제 반영 범위와 검증 제약은 변경 이력에 남기며 기존 사용자 서버·세션을 강제 종료하거나 테스트 입력을 보내지 않는다.
