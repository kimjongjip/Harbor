# Harbor 사용자 설치·실행·업데이트

## 같은 세션 이어 쓰기와 터미널 읽기 (1.16.2)

PC Harbor와 작업 중인 터미널을 켜둔 채 iPhone에서 **열린 세션**을 선택하면 같은 CLI 프로세스에 연결됩니다. 최신 화면을 받은 뒤 프롬프트를 보내세요. 다른 기기가 입력을 제어 중이면 **여기서 제어**로 인계하고, PC로 돌아온 뒤에도 같은 버튼으로 입력을 이어갑니다. 보기만 하는 연결은 제어권을 가져가지 않습니다. 휴대폰을 잠갔다 돌아왔을 때 새 연결을 확인하며, 전송 결과가 불확실한 입력을 자동으로 다시 보내지 않습니다. PC Harbor 종료·PC 전원 종료·실제 SSH 프로세스 종료까지 유지하는 독립 실행 기능은 아닙니다.

왼쪽 **대화 기록**의 제목을 누르면 세션을 실행하지 않고 가장 최근 질문·답변부터 미리 봅니다. 질문 뒤에 해당 답변이 붙는 순서는 유지합니다. 아래 **이전 대화 더 읽기**로 과거 작업을 살펴본 뒤 **터미널에서 이어가기** 또는 **옆에 열기**를 누르세요. 열어 본 기록의 목록에는 최근 질문도 표시됩니다.

PC AI 터미널은 질문·작업 출력·답변·원래 CLI 입력을 하나의 스크롤 화면에 표시합니다. 별도 대화 창이나 입력용 아래 분할 창은 없습니다. 작업 중에는 실시간 출력을 유지하고, 완료가 확인되면 중간 항목을 **작업 과정**에 접어 둡니다. 명령 실행·도구 결과·에이전트 작업은 각 줄의 화살표로 원문을 펼치고 접습니다. 오래된 기록은 완료 표시가 없어도 개별 작업을 접고 펼칠 수 있으며, 왼쪽 대화 기록 미리보기에도 같은 작업 항목이 나옵니다. **터미널 원문**은 원래 CLI 화면 확인용 보조 버튼이며, 세션이나 입력 엔진을 바꾸지 않습니다.

1.16.2는 작업 중인 최신 내용을 `Bash`·`도구 결과` 목록으로 중간 전환하지 않습니다. CLI 원문을 유지하다 완료가 확인되면 질문·작업 묶음·답변을 함께 표시합니다. 완료 정보를 모르는 이전 기록은 **저장된 작업**으로 묶습니다. 입력 시 화면 대기를 줄이고 원래 CLI의 회색 입력 배경도 유지합니다.

여러 질문·답변과 현재 출력을 연속으로 드래그하고 휠이나 화면 가장자리로 스크롤한 뒤 **Ctrl+C**로 복사할 수 있습니다. 위쪽 끝에서는 이전 기록을 더 읽으며 선택한 글과 읽는 위치를 유지합니다. 선택하거나 과거를 읽는 동안 새 출력의 화면 반영·자동 접기를 미루고, **맨 아래로** 또는 입력 재개로 최신 위치에 돌아옵니다. 긴 작업 결과는 펼칠 때 원문을 읽고 **원문 더 보기**로 계속 읽습니다. 이는 저장된 텍스트의 표시 방식이며 AI 요약·압축이나 토큰 소비가 없습니다. 원래 기록에 저장되지 않은 출력은 복원하지 않습니다.

PC IDE에서 Markdown은 읽기 화면으로 열며, 오른쪽 AI 패널은 **새 대화 / 대화 기록**에서 Codex·Claude를 직접 사용합니다. **현재 터미널 대화**로 이미 열린 CLI도 종료하지 않고 표시합니다. 새 대화는 코드 인용·질문·실행 승인을 패널 안에서 처리하고, 기존 CLI의 입력 지원 여부와 승인 처리는 [IDE 안내](desktop-ide-guide.md)를 참고하세요.

PC의 **터미널 / IDE** 전환, **다른 Harbor 연결**, 상단 연결 아이콘의 **Tailscale 설치·로그인**은 [PC IDE와 기기 연결 안내](desktop-ide-guide.md)를 참고하세요. 모바일은 세션·터미널·설정만 제공하며 승인·질문은 해당 터미널 안에서 처리합니다.

아이폰에서 같은 세션을 보려면 [Harbor Mobile 사용 안내](mobile-guide.md)를 따릅니다. 1.12.6부터 상단 휴대폰 버튼에서 **VPN 없이 연결(Funnel)**을 선택할 수 있습니다. iPhone에는 VPN이 필요 없으며 PC Harbor와 PC Tailscale은 실행 중이어야 합니다. 기존 Serve 연결도 유지됩니다.

## 처음 설치

Windows 10/11 x64, Windows PowerShell 5.1, Git, 인터넷 연결이 필요합니다.

```powershell
git clone https://github.com/kimjongjip/Harbor.git
cd Harbor
.\Setup-Harbor.cmd
```

Node.js와 Electron 등은 저장소 안에 자동 다운로드·설치하고 빌드합니다. 관리자 권한은 필요하지 않습니다. Codex·Claude는 사용할 컴퓨터/서버에 별도 설치하고 본인 계정으로 로그인해야 합니다.

설치가 끝나면 바탕화면에 **Harbor 아이콘**을 자동 생성합니다. 다음부터는 이 아이콘을 더블클릭하면 됩니다. OneDrive 등으로 바탕화면이 이동된 경우에도 Windows가 지정한 바탕화면에 만듭니다. Setup이나 Update를 다시 실행하면 기존 Harbor 바로가기의 경로도 갱신합니다. 설치 폴더를 옮겼다면 Setup을 다시 실행하세요.

작업표시줄에 고정해서 사용할 수도 있습니다. 1.3.1부터 같은 설치 폴더의 옛 EXE에 연결된 고정 아이콘은 Setup·Update에서 최신 버전을 선택하는 실행기로 갱신합니다. 새 앱에서 고정할 때도 이 실행기 경로를 사용합니다. 매번 삭제·재설치하거나 새로 클론할 필요가 없습니다. 작업표시줄의 옛 바로가기만 갱신하려면 Harbor 폴더에서 `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\create-desktop-shortcut.ps1`를 실행합니다. 이 명령은 작업 중인 앱을 종료하지 않습니다.

`Start-Harbor.cmd`를 더블클릭하거나 ` .\Start-Harbor.cmd`를 실행해도 됩니다. `Setup-Harbor.cmd -NoLaunch`는 설치·빌드와 바로가기 생성까지 하고 앱은 열지 않습니다. 바탕화면 쓰기 권한 또는 Windows Script Host 정책 때문에 바로가기를 만들 수 없으면 경고를 표시하며 앱 설치는 유지합니다.

Claude 대화 기록의 제목은 세션 이름, 사용자 지정 이름, AI 생성 제목, 요약, 질문 순으로 읽습니다. 제목이 아직 없는 기록은 내부 명령 태그 대신 실제 질문을 표시하며 명령만 있는 기록은 `/review`처럼 읽을 수 있는 명령으로 표시합니다. 목록·검색·미리보기에 같은 제목을 사용합니다.

## 세션별 실행 승인 자동 수락

1.11.1부터 **각 터미널 위쪽 방패 버튼 → 이 세션 자동 수락 켜기**를 사용합니다. 실행 중인 Codex·Claude를 다시 시작하지 않고 켜고 끌 수 있습니다. 같은 서버의 다른 세션에는 적용하지 않습니다. 연구실의 각 AI 터미널에서도 따로 켭니다. 새 터미널 창의 **이 세션의 실행 승인 요청을 Harbor가 자동 수락**을 선택해 미리 켤 수도 있습니다.

Codex·Claude가 실제 실행 승인 요청을 보내면 Harbor가 **이번만 허용**을 자동 선택해 응답합니다. 받은함에 대기 중인 해당 대화의 실행 승인도 처리하고, 받은함의 **Harbor 자동 수락** 기록과 방패 버튼의 수락 건수로 확인합니다. 이는 허용 응답 기록이며 작업 실행 성공을 뜻하지는 않습니다. 명령 실행·파일 삭제도 자동으로 허용되므로 맡길 세션에만 켜세요.

CLI 승인 정책·샌드박스는 바꾸지 않습니다. 일반 질문·계획 확인·로그인·최초 신뢰 확인은 대상이 아닙니다. Harbor 승인 연결로 전달되지 않은 확인이나 제한 시간 이후 CLI 자체 화면으로 돌아간 승인창은 직접 처리해야 합니다. 관리형 연결이 없는 터미널에는 켤 수 없습니다.

화면 새로고침은 설정을 유지하지만 **Harbor 백엔드를 재시작하거나 다른 대화로 전환하면 꺼집니다.** 터미널을 닫으면 설정도 사라집니다. 끄기는 이후 요청부터 적용하며 이미 전달한 허용 응답을 취소하지 않습니다. 모든 세션의 기본값은 꺼짐입니다.

## 서버 CLI 시작 권한 (별도 기능)

서버 관리 카드의 **방패 버튼 → 서버 CLI 시작 권한**은 1.11.0에서 추가한 별도 기능입니다. **CLI 설정 사용**은 기존 Codex·Claude 설정을 유지하고, **승인 생략 · 전체 권한**은 CLI 자체의 승인 대기를 생략합니다. 이 설정으로 CLI가 요청을 보내지 않으면 Harbor 자동 수락 기록도 생기지 않습니다. 파일 삭제, 프로젝트 밖 접근과 네트워크 명령도 확인 없이 실행될 수 있으므로 신뢰하는 작업에만 선택하세요.

저장 후 **새 터미널**을 열어 `codex` 또는 `claude`를 실행하세요. 대화 기록에서 새로 이어가기, 연구실에서 새로 만드는 AI도 이 서버의 설정을 사용합니다. 터미널 아래에는 **시작 설정: 승인 생략 · 전체 권한**을 표시합니다. 이 표시는 실행 시 전달한 설정이며 CLI 안에서 직접 바꾼 현재 모드를 감시하는 표시는 아닙니다.

이미 실행 중인 AI·열린 셸·기존 tmux 세션은 바뀌지 않습니다. 기존 대화에 적용하려면 CLI에서 대화를 종료한 뒤 새 Harbor 터미널에서 대화 기록을 이어가세요. 서버 기본값을 되돌려도 실행 중인 AI는 바뀌지 않습니다. 모든 서버의 기본값은 CLI 설정 사용이며 Harbor 밖의 전역 설정 파일은 수정하지 않습니다.

화면의 `yes`나 Enter를 자동 입력하지 않습니다. 로그인·처음 여는 프로젝트의 신뢰 확인·Claude의 최초 전체 권한 확인·작업 방향 질문·조직에서 강제한 확인은 남을 수 있습니다. 최초 실행을 확인한 뒤 장시간 작업을 맡기세요. 일반 SSH 대체 연결의 셸처럼 자동 설정을 적용할 수 없는 경로는 오류로 알립니다.

Codex에는 해당 실행의 `approval_policy="never"`, `sandbox_mode="danger-full-access"`, Claude에는 `--permission-mode bypassPermissions`를 전달합니다. CLI의 관리 정책이나 강제 확인은 그대로 적용됩니다. [Codex 승인 설정](https://learn.chatgpt.com/docs/agent-approvals-security), [Claude 권한 설정](https://code.claude.com/docs/en/permissions).

## 글꼴·읽기 설정

오른쪽 위 **글꼴·읽기 설정**(글자 모양 아이콘)을 누르면 터미널, 문서·답변, 메뉴·목록을 각각 조절할 수 있습니다. 터미널은 한글·영문 고정폭 D2Coding 15px·줄 간격 1.45배, 문서는 Pretendard 16px·1.7배가 기본입니다. 메뉴는 기존 크기 차이를 유지하며 기준 14px로 표시합니다.

슬라이더를 움직이면 즉시 바뀌며 실행 중인 셸이나 AI를 재시작하지 않습니다. 같은 Harbor 주소의 다른 창에도 적용되고 새로고침 후에도 유지됩니다. **기본값 복원**으로 되돌릴 수 있습니다. 문서 창의 Ctrl+휠 확대는 이 기본 글자 크기에 추가되는 별도 배율입니다.

두 글꼴은 앱에 포함되어 인터넷 연결이나 별도 설치가 필요하지 않습니다. 터미널 글꼴에서 Cascadia Code·Consolas를 선택하면 이 컴퓨터에 설치된 글꼴을 사용하고, 없으면 포함된 D2Coding과 한글 대체 글꼴로 표시합니다. 크기·줄 간격은 본인에게 편한 값으로 맞추세요.

## PDF 열기와 하위 폴더에 업로드

Markdown·CSV·이미지·PDF·HTML 링크는 Ctrl+클릭하면 독립 창 전체에 표시됩니다. 창을 다른 모니터로 옮기거나 크기를 조절해도 본창 터미널은 계속 사용할 수 있습니다. Markdown·텍스트 문서는 Ctrl+마우스 휠로 글자 크기를 바꾸고 내용 영역 안에서 스크롤합니다.

HTML은 `.html`·`.htm` 파일을 웹페이지로 표시합니다. 로컬·SSH의 절대경로와 상대경로, 파일명만 있는 링크를 지원하며 탐색기에서도 열 수 있습니다. 문서 폴더와 하위 폴더의 상대경로 CSS·이미지·JavaScript·JSON, HTTPS 외부 리소스를 읽습니다. **원문 보기**로 HTML 코드를 확인하고 **새로고침**으로 수정된 파일을 다시 읽습니다. 미리보기 연결은 한 시간 뒤 만료되며 새로고침으로 갱신합니다. 1.10.9부터 HTML의 20MB 제한을 없애고 내용을 조금씩 전송합니다. **원문 보기**는 처음 512KB까지 표시하며 웹페이지 표시는 전체 문서를 사용합니다. 전체 원문은 **다운로드**로 받을 수 있습니다. 문서 자체에 많은 데이터나 도형이 있으면 브라우저의 렌더링 시간·메모리는 문서 규모에 따라 늘어납니다.

HTML은 별도 격리 영역에서 실행되므로 Harbor의 세션·설정에 접근하지 못합니다. 상위 폴더의 리소스, `/assets/...`처럼 사이트 루트를 전제로 한 경로, 별도 백엔드·로그인·브라우저 저장소가 필요한 웹 앱은 그 앱의 웹 서버 주소로 열어야 합니다. HTML 미리보기는 웹 서버 실행을 대신하지 않습니다.

상대경로는 클릭한 터미널의 현재 폴더를 먼저 사용합니다. 파일이 없으면 가장 가까운 Git 저장소·worktree 루트에서 같은 경로를 확인합니다. 예를 들어 현재 폴더가 `/project/docs`이고 링크가 `docs/research/goal.md`이면 `/project/docs/docs/research/goal.md`가 없을 때 `/project/docs/research/goal.md`를 찾습니다. Git이 없는 폴더에서도 이처럼 폴더명이 한 번 중복되는 경우를 처리합니다. 실제 열린 절대경로는 창 위에, 보정한 기준 폴더는 입력란에 표시합니다. 절대경로와 `./`, `../`가 포함된 경로는 그대로 해석하며, 다른 프로젝트를 무작위로 검색하지 않습니다. 파일이 없으면 확인한 경로를 보여주므로 기준 폴더를 직접 지정할 수 있습니다.

터미널의 PDF 경로를 Ctrl+클릭하면 독립 미리보기 창에서 열립니다. 절대경로와 현재 작업 폴더 기준 상대경로를 지원하며 로컬·SSH 서버의 파일 모두 같은 방식으로 읽습니다. 파일 탐색기의 PDF도 클릭해 열 수 있습니다. PDF 창은 내장 뷰어로 페이지 이동·확대·텍스트 선택을 지원합니다.

로컬 파일을 탐색기의 하위 폴더 행 위에 놓으면 그 폴더에 업로드합니다. 대상 폴더가 강조되고 업로드할 경로가 표시됩니다. 왼쪽 트리의 닫힌 폴더에 잠시 머무르면 펼쳐져 더 깊은 하위 폴더를 선택할 수 있습니다. 빈 공간에 놓으면 현재 열린 폴더로 업로드합니다. 크게 보기 화면에서도 폴더 행에 놓을 수 있습니다. 기존 파일은 덮어쓰지 않으며 폴더를 통째로 드래그해도 하위 경로와 빈 폴더를 유지해 올립니다. 같은 이름의 대상 폴더가 이미 있으면 합치거나 덮어쓰지 않고 이름 변경·다른 위치 선택을 안내합니다. 파일 업로드 옆의 폴더 업로드 버튼으로 선택할 수도 있습니다. 폴더 선택기는 브라우저가 제공하는 파일 목록을 사용하므로 빈 폴더까지 포함하려면 드래그를 사용하세요. 한 번에 파일·폴더 합계 10,000개, 파일 하나당 512MB까지 지원합니다. 전송 중 취소할 수 있으며 이미 완료한 파일은 유지하고 쓰다 중단한 파일만 정리합니다. 업로드 준비 중 오류나 파일 권한 오류를 SSH 인증 실패로 표시하지 않습니다.

## 완료 답변의 수식·표 조판

Claude Mods의 오른쪽 패널을 켜도 남은 대화 영역의 폭에 맞춰 조판합니다. 이때 공유 PTY의 크기는 바꾸지 않습니다.

조판된 답변을 선택하는 동안에는 그 답변 안에서 휠과 위·아래 경계 드래그로 긴 내용을 읽습니다. CLI 자체 스크롤이 없는 전체 화면 모드에서도 동작하며, 선택을 마친 뒤 복사할 수 있습니다. 선택 중 스크롤은 CLI에 키를 보내지 않습니다. 바깥을 클릭하거나 선택을 해제하면 원래 터미널 위치로 돌아갑니다.

글자를 드래그한 채 휠을 굴리면 스크롤하며 선택을 이어갑니다. Codex처럼 CLI가 직접 이전 화면을 그리는 경우도 실제로 스크롤하며, 이미 화면 밖으로 나간 선택 시작점과 문장을 유지합니다. 마우스를 누른 채 터미널 위·아래 경계로 끌면 자동 스크롤합니다. 선택을 마친 뒤 **Ctrl+C**로 전체 선택을 로컬 클립보드에 복사합니다. 선택이 없으면 Ctrl+C는 원래 터미널의 중단 키이며, 휠도 CLI의 원래 스크롤 동작입니다. 새로 클릭하거나 **Esc**를 누르면 화면을 넘겨 유지하던 선택을 해제합니다.

새 출력으로 화면이 교체되거나 겹치는 문장을 확인할 수 없는 큰 페이지 이동이면, 서로 다른 내용을 이어 붙이지 않고 기존 선택을 보존했다는 안내를 표시합니다. 이때도 스크롤은 계속 가능하며 다시 드래그해 선택할 수 있습니다. 저장된 전체 대화는 기존 **대화 기록** 보기에서도 선택·복사할 수 있습니다.

업데이트 후 Harbor 터미널에서 평소처럼 `claude`를 실행하세요. Claude Code **2.1.287 이상**의 대화형 실행이면 세션 전용 UI 모드를 연결합니다. 답변이 생성되는 동안에는 기존 CLI 텍스트가 나오고, 완료 후 같은 답변 자리에 수식·표·코드·이미지를 조판합니다. 답변에 마우스를 올리면 **원문** 버튼이 나타납니다. 글을 드래그해 Ctrl+C로 복사하거나 **인용하여 질문**을 사용할 수 있고, 수식은 원래 TeX로 복사됩니다. 표의 열·행 구분도 보존합니다.

Codex는 완료한 주 대화 답변을 같은 터미널 안의 **완료 답변 조판 보기**에 표시합니다. 제목을 눌러 접거나 펼치고 목록에서 이전 답변을 선택합니다. 원래 Codex 화면과 입력칸을 유지하며 Claude처럼 원래 출력 영역을 교체하는 방식은 아닙니다. 이 보기는 답변을 다시 요청하거나 모델 설정·effort를 바꾸지 않습니다.

Codex에 Mermaid 지원 불가 안내가 나오고 완료 답변 조판을 받지 못한 경우, 1.10.5부터 **답변의 다이어그램**이 자동으로 열립니다. 현재 대화의 최근 저장된 완료 답변에서 그림을 읽으며, 여러 그림이면 목록에서 선택합니다. 제목으로 접고 펼치거나 그림의 +/− 버튼으로 크기를 바꿀 수 있습니다. 저장 직후라 아직 읽지 못했다면 **다시 읽기**를 누르세요. 원래 CLI의 지원 불가 문구 자체를 바꾸는 기능은 아니며, 오래된 답변은 아래 **대화 기록**에서도 열 수 있습니다.

Claude의 오래된 버전·비대화형 실행·지원하지 않는 크기·조판 실패에서는 네이티브 원문을 유지합니다. 조판은 백그라운드에서 처리하며 최초 글꼴·이미지 준비에 시간이 걸릴 수 있습니다. 매우 크거나 복잡한 답변에는 크기 제한이 있습니다. 글꼴 변경 뒤 높이가 늘어나면 이미 확보한 영역 안에서 스크롤합니다. SSH에서는 Harbor 연결이 살아 있어야 새 조판을 받을 수 있고 서버에 별도 브라우저나 조판 도구를 설치할 필요는 없습니다.

1.8.2부터 조판은 브라우저의 실제 문서 레이아웃으로 표시합니다. 긴 표를 이미지로 복제할 때 생기던 줄 겹침을 제거하고, 답변 첫 줄이 화면 밖에 있어도 보이는 행을 따라 표시합니다.

**기존 Claude 대화는 유지합니다.** 1.8.0·1.8.1에서 실행한 Claude는 잘못된 큰 공백을 남기지 않도록 네이티브 원문으로 돌아가고, 완료 답변은 접힌 **완료 답변 조판 보기**에서 읽을 수 있습니다. 새 Claude 실행부터 원래 답변 위치의 새 표시 방식을 사용합니다. 조판 원문은 개인 데이터 폴더의 `rich-answers.json`에 보관되므로 다른 사람에게 전달하지 마세요.

## 현재 터미널의 이전 대화 읽기

1.15.4부터 Claude 기록 파일이 16MB를 넘어도 열 수 있습니다. 파일 전체를 한꺼번에 불러오지 않고 최근 메시지부터 나누어 읽습니다. **개별 기록 항목 하나**가 8MB를 넘으면 안내를 표시하고 건너뛰며, 원본 파일은 변경하지 않습니다. 도구 출력만 있는 구간에서도 이전 대화를 계속 불러올 수 있습니다. 이 수정은 서버 코드에 포함되므로 기존 앱을 사용 중이었다면 작업을 정리한 뒤 Harbor를 다시 실행해야 합니다.

화면만 먼저 업데이트된 상태에서는 구버전 서버의 16MB 오류를 반복 표시하거나 자동 재요청하지 않고 이미 읽은 내용을 유지합니다. 큰 기록 전체를 읽으려면 서버가 포함된 새 Harbor를 실행한 뒤 기록을 새로고침하세요.

터미널 아래의 **대화 기록**을 누르면 지금 열려 있는 Codex·Claude 대화의 저장된 메시지를 같은 터미널 안에서 읽습니다. 위로 스크롤하면 이전 메시지를 더 불러오며 **이전 메시지 더 보기**로 직접 읽을 수도 있습니다. 원래 CLI·모델·대화·작성 중인 입력은 유지하고 아래의 터미널 입력창을 계속 사용할 수 있습니다. 읽기 창을 닫으면 터미널 화면이 그대로 남습니다.

Claude fullscreen은 대체 화면을 사용하므로 오른쪽 터미널 스크롤바에 전체 대화가 쌓이지 않습니다. 휠과 PgUp/PgDn은 Claude 내부의 대화를 스크롤하며 Ctrl+Home은 처음, Ctrl+End는 최신 위치로 이동합니다. Harbor 1.8.3은 관리형 tmux의 마우스 전달을 활성화하고 기존 유지 세션의 재연결에도 적용합니다. [Claude fullscreen 안내](https://code.claude.com/docs/en/fullscreen#use-with-tmux)

요약된 Claude 대화를 재개한 경우 Claude 화면은 마지막 요약 경계 이전까지 스크롤되지 않을 수 있습니다. 이때 화면에 최신 내용만 남아 있어도 파일의 이전 대화가 지워졌다는 뜻은 아닙니다. **대화 기록**은 저장된 원문을 읽으므로 그 이전 내용도 페이지를 넘겨 확인할 수 있습니다. 서버 인증·파일 크기·접근 권한 등의 문제는 기록 창에 표시하며 읽던 메시지를 보존한 채 다시 시도할 수 있습니다.

## 왼쪽 패널 너비 조절

서버·파일·받은 요청 패널의 오른쪽 경계를 드래그하면 너비가 바뀝니다. 조절한 너비는 이 컴퓨터에 저장되어 패널을 접었다 펼치거나 새로고침해도 유지됩니다. 터미널 공간을 확보하도록 최소·최대 너비를 제한합니다.

경계를 두 번 클릭하면 해당 패널의 기본 너비로 돌아갑니다. 키보드로 경계에 초점을 맞춘 뒤 좌우 방향키로 조절할 수도 있습니다. Shift를 누르면 더 크게 조절하고 Home 또는 Enter로 기본 너비로 돌아갑니다.

## SSH 연결 방식 선택과 유지 세션

**1.8.5부터 새 SSH 터미널은 일반 SSH로 직접 연결하며 tmux를 자동 실행하지 않습니다.** 대화 기록 재개와 연구실도 같은 기본 연결을 사용합니다. 서버의 Bash와 TCP forwarding을 사용할 수 있으면 기존 Harbor의 AI 훅·인용·조판 연동을 그대로 제공합니다. SSH keepalive는 연결 확인을 위해 계속 사용합니다. PC가 절전되지 않아도 네트워크·서버·SSH·Harbor의 문제가 생길 수 있으며, 끊김의 원인은 진단 없이 PC 절전으로 단정하지 않습니다.

**1.9.0부터 새 터미널 → SSH 서버 선택 → SSH 세션 방식**에서 **일반 SSH (기본)** 또는 **서버에서 세션 유지 (tmux)**를 고릅니다. 이 선택은 이번에 여는 터미널에만 적용되며 다음 새 터미널이나 서버 변경 시에는 일반 SSH로 시작합니다. 로컬에는 이 항목이 없습니다. tmux를 선택했는데 서버에 tmux·bash가 없으면 연결을 중단하고 안내하며, 일반 SSH로 자동 대체하지 않습니다. 설치 후 재시도하거나 직접 일반 SSH로 바꾸세요. tmux 터미널의 셸에서도 평소처럼 `codex`, `claude`, `codex resume`, `claude --resume`을 실행할 수 있습니다.

일반 SSH는 아래에 **일반 SSH 연결**로 표시합니다. 연결이 종료되면 원격 작업도 종료될 수 있습니다. 서버가 실제로 보고한 종료 코드·신호가 있을 때만 원격 종료로 표시하며, 전송이 끊겨 상태를 모르면 **SSH 연결 끊김**과 원격 종료 상태 미확인을 표시합니다. 해당 항목은 X로 정리하고 새 터미널로 연결할 수 있습니다. 일반 SSH를 원래 프로세스에 자동으로 다시 붙이는 기능은 없습니다.

tmux를 선택한 새 터미널과 1.8.0~1.8.4에서 만든 기존 tmux 세션은 **서버에서 세션 유지**로 표시합니다. 업데이트 과정에서 실행 중인 작업을 종료하거나 연결 방식을 강제 전환하지 않습니다. 다음 표는 이 유지 세션에 해당합니다.

| 동작 | 유지 세션의 동작 |
| --- | --- |
| 화면 새로고침·창 크기 변경 | 실행 중인 서버 작업을 유지합니다. |
| 네트워크 단절·PC 절전 | 서버 작업을 유지하고 연결 복구를 재시도합니다. 연결 중에는 터미널 입력을 보내지 않습니다. |
| Harbor 완전 종료·업데이트 | 서버 연결만 분리합니다. 같은 설치·데이터로 다시 실행하면 원래 세션을 복구합니다. 로컬·일반 SSH 프로세스는 종료됩니다. |
| 터미널 탭·서버 목록의 X → 터미널 종료 | 해당 서버의 유지 세션과 실행 중 프로그램을 종료합니다. 종료를 확인하지 못하면 목록을 보존합니다. |
| 서버 재부팅·외부에서 유지 세션 종료 | 프로세스를 복원하지 않습니다. 세션을 찾지 못했다는 사유를 표시하며 CLI를 자동으로 새로 실행하지 않습니다. |

**서버에 다시 연결 중…**은 SSH 연결을 복구하는 상태입니다. 연결 오류를 정상 종료로 표시하지 않으며 입력을 모아두었다가 자동 재전송하지 않습니다. 인증 실패가 표시되면 **다시 연결**에서 저장된 인증·SSH 키를 사용하거나 비밀번호를 입력하세요. Harbor 훅·MCP 연결도 기존 포트와 인증으로 복원합니다. 기존 포트를 다른 프로세스가 사용하거나 TCP forwarding이 차단되면 포트를 임의로 바꿔 새 CLI를 실행하지 않고 연결 사유를 표시합니다. 서버 주소·사용자·포트·키 설정이 바뀐 경우에도 이전 작업을 다른 대상으로 옮기지 않습니다.

**서버 세션 없음**은 SSH 접속 후 원래 tmux 세션이 사라진 것을 확인했다는 뜻입니다. 서버 재부팅 등으로 없어진 프로세스는 재연결로 복원되지 않습니다. 해당 터미널의 X → **터미널 종료**로 오래된 항목을 정리하고, 필요한 대화는 왼쪽 대화 기록에서 새 터미널로 이어가세요. **서버 세션 상태 확인 필요**는 접근 권한·관리 명령 등의 문제로 아직 확인하지 못한 상태이며, 작업이 계속 실행 중이라고 보장하는 표시가 아닙니다. 확인 실패 시 목록을 보존하고 일시적인 오류의 재연결을 계속 시도합니다. 1.8.4는 tmux 3.2a의 오류 문구 때문에 사라진 세션을 닫지 못하던 문제도 수정합니다. 이미 실행 중인 이전 앱에는 새로고침만으로 적용되지 않으므로 완전 종료 후 다시 실행해야 합니다.

앱이 꺼져 있는 동안 서버의 CLI는 계속 실행될 수 있지만 Harbor 받은함·연구실 배정·인용 훅은 Harbor가 다시 연결될 때까지 사용할 수 없습니다. 앱 재시작 후 연구실 기록은 일시정지로 복구되므로 원래 참여자 연결을 확인한 뒤 **계속 진행**하세요. 이는 서버 프로세스를 새로 만드는 동작이 아닙니다.

진단은 Harbor 개인 데이터 폴더의 `terminal-disconnects.jsonl`에 시각·터미널 ID·연결 상태·오류 분류와 데스크톱 절전·복귀 이벤트만 기록합니다. 이 진단에는 명령 입력·답변 원문·주소·인증 정보를 넣지 않습니다. 과거 밤사이 종료의 원인은 이전 버전에 기록이 없으면 확정할 수 없으며, 새 기록으로 네트워크·전원·서버 종료를 구분합니다. 유지 세션 목록인 `durable-terminals.json`과 인용 데이터인 `terminal-annotations.json`도 개인 데이터 폴더에 있으므로 `.data` 등을 지우거나 다른 사람에게 전달하지 마세요. 이 기능은 다른 PC·휴대폰과의 공통 세션 서비스는 아닙니다.

## 인용하여 질문

터미널 답변에서 글을 드래그해 선택하고 `인용하여 질문`을 누르면 해당 터미널 아래에 작은 입력 패널이 열립니다. 선택한 내용은 `[#1 annotation]`처럼 표시됩니다. 다른 부분을 선택해 추가하면 새 번호가 붙습니다. 번호는 서버가 할당하므로 다른 창에서도 중복되지 않습니다.

번호를 누르면 선택한 원문과 출처를 확인하고 그 부분에 대한 질문·코멘트를 작성할 수 있습니다. 각 번호는 원문과 해당 코멘트를 함께 담는 첨부 항목입니다. 다른 부분을 추가하면 새 번호의 코멘트를 작성하며, 이전 번호를 누르면 기존 코멘트를 다시 확인·수정할 수 있습니다. 옆의 ×로 해당 참조를 삭제해도 나머지 번호의 내용은 유지됩니다. 한 번에 최대 8개를 붙일 수 있습니다.

`입력에 추가` 또는 Ctrl+Enter를 누르면 실제 CLI 입력칸에는 `[#1 annotation]` 같은 번호만 들어갑니다. 인용 원문과 그 번호에 작성한 질문·코멘트는 번호 안에 연결되어 있으며 입력칸에 풀어서 표시하지 않습니다. 터미널에서는 번호 뒤에 일반 질문을 계속 작성할 수도 있습니다. 자동으로 전송하지 않으며 터미널에서 Enter를 눌러 보냅니다.

선택한 본문과 해당 번호에 작성한 질문·코멘트는 Harbor가 보관하다가 CLI의 `UserPromptSubmit` 훅에서 별도 문맥으로 함께 전달합니다. 원문·코멘트·출처는 입력칸에 나타나지 않습니다. 선택한 원문과 서버·터미널·작업 폴더를 연결하고 앞뒤 글은 추가하지 않습니다. 해당 터미널과 대화에 속한 번호만 사용할 수 있습니다.

이는 VS Code 확장의 내부 구현과 동일하다는 뜻은 아닙니다. 공식 VS Code 확장 패키지에서도 선택문·주석·출처를 별도 문맥으로 직렬화하는 코드를 확인했지만, Harbor는 네이티브 CLI 훅을 사용하며 입력칸의 번호는 편집 가능한 텍스트입니다. Codex CLI 0.160.0에서 기본 연결을 검증했고, 0.160.1에서 번호만 보이는 입력 화면과 인용 원문·코멘트가 함께 전달되는 것을 검증했습니다. 훅 연결을 사용할 수 없을 때 본문을 대신 붙여 넣는 경로는 없습니다. 앱 업데이트는 실행 중인 Codex에 새 훅을 추가하지 않으므로 작업을 저장한 뒤 Harbor와 Codex를 다시 실행해야 합니다.

참조의 원문·주석·출처·네이티브 대화 연결과 번호는 Harbor 개인 데이터 폴더에 보관합니다. 유지 SSH 세션으로 앱을 다시 연결해도 원래 번호가 원래 선택문을 가리키며, 다른 대화에서 그 번호를 사용할 수 없습니다. 참조를 삭제하거나 해당 터미널을 명시적으로 종료하면 더 이상 연결할 수 없고, 삭제된 번호를 새 선택문에 재사용하지 않습니다. 로컬·일반 SSH 세션은 앱 종료 시 종료되므로 재시작 후 같은 실행 세션으로 복구되지 않습니다. 이미 전송한 선택문은 CLI 대화 문맥에 포함됩니다.

## 다른 세션에 질문·답장

1. 로컬 또는 SSH 터미널을 둘 이상 열고 각 터미널에서 `codex` 또는 `claude`를 실행합니다.
2. 터미널 이름 변경 버튼으로 `구현`, `리뷰`처럼 서로 다른 이름을 정합니다. 같은 이름이 여러 개면 AI가 대상을 다시 구분해야 합니다.
3. 구현 세션에 “리뷰 세션에 이 구조를 선택한 이유를 물어보고, 답을 반영해서 계속 진행해줘”라고 요청합니다. 도구 이름이나 내부 ID를 프롬프트에 적을 필요는 없습니다.
4. 왼쪽 **받은함 → 메시지**에서 요청·답장과 실제 전달 상태를 확인합니다. 세션 목록을 누르면 해당 터미널로 이동합니다.

Codex↔Codex, Codex↔Claude, Claude↔Claude가 같은 받은함을 사용합니다. 같은 서버와 서로 다른 SSH 서버에도 같은 이름 기반 도구를 사용합니다. 답변은 새 AI 대화를 만들어 추측하는 방식이 아니라 상대의 실행 중인 네이티브 대화에서 작성됩니다. AI가 도구를 실제로 호출해야 전달되며, 자동으로 도구를 선택하는 빈도까지 보장하지는 않습니다.

| 표시 | 의미 |
| --- | --- |
| 자동 수신 | Codex 네이티브 대기열 연결. 작업 중에는 현재 작업이 끝난 뒤 요청을 처리합니다. |
| 채널 수신 요청 | Claude 채널을 요청한 연결. Claude의 계정·조직 정책과 CLI가 실제로 허용해야 자동 수신됩니다. |
| 기존 대화 · 다음 활동에서 수신 | 채널 없이 시작한 Claude의 연결된 훅으로 다음 입력·도구 완료·응답 완료 때 전달합니다. 이미 입력 대기 중이면 확인 요청에 Enter가 한 번 필요합니다. |
| 받은함 확인 필요 | 상대 CLI에 “받은 메시지 확인해줘”라고 요청합니다. |
| CLI 알림 전달 · AI 확인 대기 | CLI 전송 경로가 알림을 받았지만 AI가 읽었다는 증거는 아직 없습니다. |
| AI 확인 | 수신 AI가 인증된 메시지 도구로 실제 메시지를 읽었습니다. 작업 완료를 의미하지는 않습니다. |
| 답장 도착 | 해당 질문 ID에 연결된 실제 답장이 왔습니다. |
| 원래 대화 연결 대기 | 받는 터미널이 다른 대화로 바뀌었습니다. 이전 질문을 새 대화에 자동으로 넣지 않습니다. |

Codex 자동 수신은 CLI 0.160.1 이상의 실험적 app-server·네이티브 대기열을 사용합니다. 지원하지 않거나 연결에 실패하면 받은함 방식으로 남습니다. 실행 중인 터미널에 Enter나 명령을 자동으로 입력하지 않으므로 작성 중인 프롬프트는 유지합니다. 기존에 실행한 CLI에는 업데이트만으로 새 연결이 생기지 않으므로 작업을 저장하고 Harbor와 CLI를 다시 실행하세요.

공유 서버를 지원하는 Codex에서 기존 대화를 `resume`하면 네이티브 공유 서버가 소유한 원래 대화를 사용합니다. 이를 별도 Harbor app-server에 중복으로 열어 잠금 오류를 만들지 않습니다. 이 실행은 **Codex 공유 세션 · 받은함 확인 방식**으로 표시되며 새 자동 수신 연결을 추가하지 않습니다. 새 대화를 시작하는 기존 자동 연결 경로는 유지합니다. 다른 실행이 소유한 대화의 잠금 파일이나 프로세스를 임의로 삭제·종료하지 않습니다.

Claude 자동 수신을 요청하려면 `claude --harbor-peers`를 실행합니다. Harbor는 이를 해당 실행의 `--dangerously-load-development-channels server:harbor`로 바꾸고 세션 전용 MCP 설정을 추가합니다. 이 플래그는 Claude 개발 채널 허용 목록을 위한 옵션이며 명령 실행 승인을 대신하지 않습니다. Claude의 채널 확인 안내는 CLI에서 처리합니다. `-p`/`--print` 실행에서는 자동 채널을 요청하지 않습니다. 전역 Claude 설정은 변경하지 않습니다. 채널을 사용할 수 없다는 안내가 나오면 일반 받은함 도구를 사용하세요.

**기존 Claude를 연구실에 참여시킬 때 매번 종료할 필요는 없습니다.** Harbor에서 일반 `claude`로 연 대화에는 세션 전용 훅이 연결됩니다. 채널 없이 시작했어도 같은 대화의 다음 입력·도구 완료·응답 완료 때 과제와 질문을 받으며, 응답 완료 훅은 새 메시지가 있을 때만 네이티브 Claude에 이어서 처리하도록 요청합니다. 이미 전달한 메시지는 훅에서 반복하지 않습니다. Claude의 훅 계속 진행 제한과 실행 승인은 유지합니다. [Claude 훅 공식 안내](https://code.claude.com/docs/en/hooks)

이미 입력 대기 중인 Claude에 과제를 보냈다면 연구실의 **받은 과제 확인 요청**을 누르고 원래 입력칸에서 Enter로 보내세요. 기존 입력은 지우지 않고 요청문을 뒤에 추가합니다. 자동 Enter·강제 재시작은 하지 않으며 입력 연결이 준비되지 않았다면 **확인 요청 복사**를 사용합니다. 작업 중에는 현재 도구·응답 완료를 기다리세요. 중단·실패·실행 승인 알림에는 이 계속 진행 요청을 넣지 않습니다. 일시정지하거나 완료한 과제, 다른 대화·오래된 지시의 메시지도 새 작업으로 전달하지 않습니다.

입력 대기 중에도 즉시 받는 **채널 수신**은 별도의 시작 옵션이므로 실행 중인 Claude에 나중에 켤 수 없습니다. 필요하면 다음 실행에서 `claude --harbor-peers --resume <원래 대화 ID>`를 사용하세요. 이미 채널로 실행한 대화는 그대로 사용하며 훅에서 중복 전달하지 않습니다. 계정·조직 정책·CLI 버전의 채널 제한은 우회하지 않습니다. 훅 없이 Harbor 밖에서 시작한 CLI는 이 경로를 바로 붙일 수 없으므로 받은함을 직접 확인하거나 다음에 Harbor에서 같은 대화를 재개합니다. **CLI 전달·AI 확인·결과 제출·답장**은 서로 다른 상태입니다. [Claude 채널 공식 안내](https://code.claude.com/docs/en/channels)

관리형 SSH는 연결된 서버의 `python3`와 SSH TCP forwarding을 사용합니다. 일반 OpenSSH 대체 연결에서는 자동 메시지 연결을 제공하지 않습니다. Harbor 종료 시 로컬·일반 SSH의 터미널과 전용 app-server는 종료됩니다. **서버에서 세션 유지**인 SSH는 서버의 같은 CLI·app-server를 유지하고 재연결하며, 앱이 꺼져 있는 동안 Harbor 메시지는 전달하지 못합니다. 메시지는 `.data/mailbox.json`에 보관되지만 종료한 네이티브 대화를 새 대화에 임의로 연결하지 않습니다.

현재 Codex의 SSH 자동 수신 helper는 Linux에서 지원합니다. 다른 원격 운영체제는 받은함 방식으로 돌아갑니다. 실제 네이티브 검증은 Windows의 Codex 0.160.1과 Claude 2.1.258에서 격리한 모의 모델로 수행했습니다. 실제 원격 서버·계정의 자동 채널 허용 여부와 자연어에서의 자율적인 도구 선택 품질까지 검증한 것은 아닙니다.

응답을 기다리는 도구는 최대 50초 뒤 대기 중인 질문 ID를 돌려줍니다. 이 경우 AI는 결과 조회 도구로 답장을 확인하거나, 자동 수신이 가능한 세션에서는 나중에 도착한 답장을 처리할 수 있습니다. 대기 중이라는 결과를 동의·완료로 간주하지 않습니다. 다른 AI의 메시지는 작업 문맥이며 사용자의 새 실행 승인으로 취급하지 않습니다.

## 대화 기록 열기와 분할 배치

서버 이름을 한 번 클릭하면 해당 서버의 기록을 볼 수 있습니다. 새 터미널이 필요하면 서버 옆 **+**를 누르세요. 대화 기록의 오른쪽 **옆에 열기** 버튼은 현재 창 오른쪽에 해당 대화를 재개합니다. Codex와 Claude 기록 모두 로컬·SSH 서버에서 사용할 수 있습니다.

1.9.1부터 원격 대화 기록의 **SSH 방식**(미리보기에서는 **이어갈 SSH 방식**)에서 **일반 SSH (기본)** 또는 **서버에서 세션 유지 (tmux)**를 선택합니다. 선택한 방식은 목록의 **옆에 열기**, 기록을 터미널로 **드래그**, 미리보기의 **터미널에서 이어가기·옆에 열기**에 모두 적용됩니다. 미리보기에서도 바꿀 수 있습니다. 서버를 바꾸면 일반 SSH로 초기화하며 로컬 대화에는 적용하지 않습니다. 이미 열린 대화는 기존 터미널로 이동하므로 그 연결 방식은 유지됩니다. 방식을 바꾸려면 작업을 저장하고 기존 터미널을 종료한 뒤 기록에서 다시 여세요.

기록이나 열린 터미널 탭을 터미널 **중앙**에 놓으면 그 자리에서 열고, **왼쪽·오른쪽·위쪽·아래쪽**에 놓으면 해당 창을 분할합니다. 드래그 중 강조 영역으로 위치를 확인하세요. 화면 바깥 테두리 24px 안에 놓으면 전체 배치를 분할합니다. 예를 들어 두 창 아래의 바깥 테두리에 놓으면 가로로 넓은 세 번째 창이 생깁니다. 이미 보이는 탭을 중앙에 놓으면 두 창의 자리를 바꿉니다. 다른 탭은 유지됩니다.

창이 하나면 전체 터미널 공간을 채웁니다. 분할선을 드래그하면 크기를 조절하고, 분할선이 만나는 동그란 손잡이는 가로·세로를 함께 조절합니다. 분할선 더블클릭으로 같은 비율을 복원합니다. 창을 닫으면 빈 칸을 합치며 새로고침 후 배치와 비율을 복원합니다. 제목을 클릭하거나 **Alt+PageDown**으로 분할 창 사이를 이동하세요. 상단 1·2·3·4분할 버튼으로 배치를 다시 정할 수도 있습니다.

처음 실행할 때 자동 생성한 로컬 셸은 입력한 적이 없으면 대화를 여는 과정에서 정리합니다. 직접 입력했거나 AI가 연결된 셸과 기존 작업 터미널은 자동으로 닫지 않습니다.

## 연구실에서 대화로 주제 준비하기

왼쪽 **연구실 → +**에서 먼저 이야기할 AI와 실행 서버, 프로젝트 폴더를 선택합니다. 이름은 선택 사항이며 처음부터 주제나 완료 기준을 정할 필요는 없습니다. **로컬과 저장된 SSH 서버 모두** 사용할 수 있습니다. 폴더는 선택한 서버 기준이며 `~`와 절대경로를 지원합니다.

**새 AI 대화로 시작**은 Claude 또는 Codex 한 명만 엽니다. **열려 있는 대화에서 이어서**는 기존 CLI 세션을 재시작하지 않고 연구실의 주 대화로 선택합니다. 기록에서 원하는 대화를 먼저 열고 연구실을 만들 수도 있습니다. 평소처럼 여러 번 질문하고 답하며 배경·조건·방향을 정하세요. 준비 상태에는 자동 토론·실험 배정이나 두 번째 AI 생성이 없습니다.

충분히 논의한 다음 **대화로 계획 정리**를 누르면 주 대화의 AI에게 계획 정리를 요청합니다. AI는 실제 논의에 바탕을 둔 목표, 완료 기준, 배경과 열린 질문을 `harbor_lab_plan` 도구로 제안하고 부족한 방향은 사용자에게 물을 수 있습니다. 제안 저장만으로 공동 작업은 시작하지 않습니다. 자연어로 계획을 저장해 달라고 요청하거나 **직접 계획 작성**으로 작성할 수도 있습니다.

**계획 정리 요청 상태**에서 전달 대기·CLI 전달·AI 확인·계획 저장 완료를 구분합니다. 이 상태는 새로고침 후에도 받은함 기록에서 복구합니다. **자동 수신 꺼짐 · 직접 전달 필요**라면 버튼이 주 대화 입력칸에 요청문을 추가합니다. 기존 입력은 유지되므로 내용을 확인하고 **Enter로 전송**하세요. 입력칸이 준비되지 않았거나 별도 창에 있어 추가하지 못하면 **요청문 복사**로 Ctrl+V 후 Enter를 사용할 수 있습니다. 자동 수신을 켜기 위해 기존 CLI를 강제로 재시작하지 않습니다. 자동 Claude가 답변 중이면 요청은 현재 답변이 끝난 뒤 전달됩니다.

새 주 대화의 **모델**과 **추론 노력**을 지정할 수 있습니다. 모델은 CLI에서 사용하는 정확한 ID를 입력하고, Claude는 `opus`, `sonnet`, `haiku`, `fable` 등의 별칭도 사용할 수 있습니다. 모델 입력을 비우면 해당 서버의 CLI 기본 모델을 사용합니다. 테스트용 초기 effort는 **낮음**이며 필요하면 CLI 기본 설정이나 다른 수준을 선택하세요. Codex에는 해당 실행의 `--model`과 `model_reasoning_effort`, Claude에는 `--model`과 `--effort`를 전달합니다. 모델·effort를 모두 기본으로 두면 별도 지정 옵션을 전달하지 않습니다.

**공동 작업 준비 → 추가 AI 설정**에서도 새로 참여할 AI의 모델·effort를 별도로 지정합니다. 주 대화와 다른 값을 줄 수 있고, 추가 AI 종류를 바꾸면 모델 입력을 비우며 그 AI에서 허용하지 않는 effort는 낮음으로 돌립니다. 지원되는 모델·effort는 해당 서버의 CLI 버전·선택한 모델·로그인 계정에 따라 다릅니다.

새 Codex 설정에서는 선택한 서버의 네이티브 `model/list`로 사용 가능한 **정식 모델 ID·지원 effort**를 확인합니다. 입력 목록에서 모델을 선택하고, 목록에 없는 추론 노력은 지원 값으로 직접 변경하세요. `Astra`는 `gpt-6-astra`로 처리하지만 그 계정에서 사용할 수 있는지는 별도로 검증합니다. 모델 목록을 읽지 못하거나 설정이 지원되지 않으면 터미널·worktree 생성 전에 오류를 보여줍니다. 두 값을 모두 CLI 기본 설정으로 두면 별도 지정값 검증 없이 네이티브 설정을 유지하며 로그인부터 진행할 수 있습니다. 모델 목록 조회는 독립된 읽기 전용 연결이며 추론·대화 시작·재개 요청을 보내지 않습니다. Claude 별칭은 해당 Claude CLI가 처리합니다. [Codex 모델 목록 계약](https://learn.chatgpt.com/docs/app-server), [GPT-6 Astra 정식 ID](https://developers.openai.com/api/docs/models/gpt-6-astra)

Codex가 실제 턴 실패를 알리면 연구실은 미완료 배정을 일시정지하고 오류를 표시합니다. 해당 터미널의 `/model`·로그인·한도 안내로 원인을 해결한 뒤 **계속 진행 → 배정 알림**을 누르세요. 원래 대화·지시 버전·현재 단계·제출된 보고서는 유지하고 아직 제출하지 않은 과제만 다시 알립니다. 이미 전달된 작업·실험을 자동 종료하거나 모델·effort를 임의로 바꾸지 않습니다. 준비 중 주 대화의 실패는 공동 작업을 시작하지 않고 오류를 표시합니다.

이미 대화 중인 AI는 **터미널에서 모델·effort 확인 / 변경**을 눌러 같은 대화에서 변경합니다. Codex는 `/model`을 사용하고 지원하는 CLI에서는 `/reasoning`으로 effort를 선택할 수 있습니다. Claude는 `/model`·`/effort`를 사용하며 effort 슬라이더에서 **s**를 누르면 이번 세션에만 적용합니다. **열려 있는 대화 선택**으로 참여시킨 AI의 모델·effort를 Harbor가 덮어쓰지 않습니다. [Codex 명령 안내](https://learn.chatgpt.com/docs/developer-commands), [Claude 모델 설정](https://code.claude.com/docs/en/model-config).

왼쪽 **실행 시 지정한 설정**은 Harbor가 시작할 때 전달한 값입니다. CLI에서 이후 변경한 값을 자동 추적한 현재 설정은 아니므로 실제 값은 터미널에서 확인하세요. Harbor가 만든 세션의 원래 대화를 다시 열 때는 저장한 실행 설정을 전달합니다. 기존 대화의 재개는 그 CLI의 기록과 설정을 따릅니다. Harbor의 실행 옵션은 사용자·프로젝트의 전역 설정 파일을 수정하지 않습니다.

## 준비한 대화로 공동 작업 시작하기

**계획 확인 · 공동 작업 시작**에서 지금 맡길 일을 충분히 적고 작업 종류를 선택합니다. 배경·결정·조건과 완료 기준을 수정하고 **계획만 저장**하여 주 대화로 돌아갈 수도 있습니다.

직접 작성하는 계획은 **지금 두 AI에게 맡길 일**과 **완료 기준**을 입력해야 저장됩니다. 기준은 한 줄에 하나, 1~12개이며 각 줄은 1,000자까지 가능합니다. 계획 작성·저장은 주 대화 연결이나 대화 기록 조회가 실패해도 사용할 수 있습니다. 저장 성공을 왼쪽에 표시합니다. 저장·시작에 실패하면 입력을 보존하고 버튼 영역에 오류를 표시하므로 수정 후 다시 누르세요.

**공동 작업 시작**이 비활성화되면 버튼 옆에 대기 이유를 표시합니다. 대화 기록을 읽는 중에는 기다리거나 계획만 저장할 수 있고, 실패하면 **대화 기록 다시 불러오기**로 재시도할 수 있습니다. 원래 대화 연결, 필수 항목, 현재 답변의 완료, 추가 AI 선택도 이곳에서 확인합니다.

시작 시 주 대화의 실제 사용자·AI 메시지를 읽어 추가 AI에게 공유합니다. **주 대화 기록 공유**에서 내용을 미리 확인하세요. 최신 기록 페이지의 텍스트 최대 32,000자를 공유하고 생략 여부를 표시합니다. 이미지 원본·도구 출력·숨겨진 추론은 포함하지 않습니다. 오래된 중요한 결정은 배경에도 요약하세요. 기록을 읽지 못하면 자동으로 빈 맥락을 전달하지 않습니다. 기록을 확인하거나 **대화 기록 대신 위에 작성한 배경만 공유**를 명시적으로 선택하고 배경을 입력해야 합니다.

새 추가 AI의 종류·서버를 선택하거나 열려 있는 다른 대화를 참여시킵니다. 같은 종류의 AI끼리도 가능하며 다른 서버의 기존 대화도 연결할 수 있습니다. 다른 서버에서 새 AI를 만들면 그 서버의 프로젝트 폴더를 지정합니다. **공동 작업 시작**을 눌렀을 때만 두 AI에게 배정합니다. 주 대화의 터미널·네이티브 대화 ID는 그대로 유지됩니다. 계획이 바뀌었거나 주 대화의 답변이 진행 중이면 최신 계획과 답변을 확인한 뒤 시작하세요.

SSH 서버에는 로그인된 Codex·Claude CLI와 Bash·python3가 필요하며 코드 과제에는 Git도 필요합니다. 관리형 SSH 연결과 서버의 TCP forwarding 허용이 있어야 자동 메시지를 수신합니다. 일반 SSH 터미널 연결과 연구실의 자동 수신 가능 여부는 다르며, 수신 제한은 연구실 연결 상태에서 확인할 수 있습니다.

CLI의 최초 프로젝트 신뢰·Claude 개발 채널 안내는 해당 터미널에서 확인합니다. Claude의 **채널 수신 요청**은 CLI가 허용했다는 보장이 아닙니다. **AI 확인**과 **결과 제출**이 실제 읽기와 응답의 증거입니다. 채널 없이 시작한 기존 Claude는 연결된 훅에서 다음 활동 때 수신합니다. 응답을 마친 뒤 도착한 후속 메시지도 입력 대기 중이면 확인 요청에 Enter가 필요합니다. 훅도 없으면 받은함 확인 방식으로 남습니다. 새 배정을 넣기 위해 사용자가 작성 중인 프롬프트를 제출하지 않습니다.

두 AI는 먼저 독립적으로 분석하고, 실제 제출된 상대의 의견을 읽어 검토합니다. 해결할 쟁점이 있으면 조사·수정·실험을 진행하고 다시 검토합니다. 이후 한 AI가 결과를 정리하고 상대가 완료 기준을 최종 확인합니다. **고정된 토론 횟수로 종료하지 않습니다.** 확인이 필요한 사용자 판단이나 반복되는 정체는 확인 요청으로 표시하며 완료로 간주하지 않습니다. 중간 추천안은 **현재 결과**에 계속 보관합니다.

**후보 선택·가정·해석·비교 방법 같은 일반 질문은 AI끼리 처리**합니다. 보고서의 질문은 상대 AI에게 자동 전달하고, 초기 분석 때 나온 질문도 양측 제출 뒤 상호 검토에서 다룹니다. AI는 네이티브 메시지 도구로 후속 질문과 답장을 할 수 있습니다. 왼쪽 **AI끼리 질문·검토**를 펼치면 전달 대기·CLI 전달·AI 확인·답변 도착을 구분해 볼 수 있습니다. 전달 알림만으로 AI가 답한 것으로 표시하지 않습니다. 서로 답변을 기다리며 멈추기보다 할 수 있는 조사와 검토를 계속하도록 안내합니다.

**공동 작업 시작** 이후에는 후보 선택, 실패한 출발 후보의 확대, 조사 전략, 작업 분담, 다음 실험과 허용된 계획 수행을 두 AI가 결정합니다. 예를 들어 “처음 후보들이 모두 탈락했으니 다른 측정 병목을 찾아보자”는 연구 결정은 상대 AI에게 보내고 다음 작업으로 이어집니다. 사용자가 제시한 고정 하드웨어·예산·보호 자원과 완료 기준은 유지하며, 연구 방향을 고르라는 질문이나 같은 검토의 반복만으로 사용자 답변을 기다리지 않습니다. 정비만으로 목표를 대체하거나 기준을 낮춰 성공으로 표시하지 않습니다.

정말로 **고정 하드웨어·예산·보호 자원의 변경, 사용자만 제공할 수 있는 필수 정보, 허가받지 않은 외부 작업**이 필요한 경우에만 동료 AI의 실제 답변으로 먼저 검토한 뒤 **사용자 결정 요청**으로 표시합니다. 고정 제약 변경은 사용자가 명시한 제약의 원문과 제안한 변경을 함께 보여줍니다. 요청 이유와 **동료 AI의 답변**을 확인하고 **사용자 결정에 답변 → 답변하고 이어가기**를 누르세요. 기존 분석과 단계에서 이어갑니다. 네이티브 CLI의 실행·파일·보안 승인은 유지하며 AI끼리 승인할 수 없습니다.

공동 연구 중 일반 `harbor_request` 질문은 사용자 받은함 대신 동료 AI에게 전달합니다. 모델은 반환된 질문 ID와 `harbor_ask_result`로 실제 답변을 확인할 수 있고 준비 단계와 연구실 밖의 일반 사용자 질문은 기존 방식입니다. CLI가 도구를 쓰지 않고 입력칸에서 직접 질문하는 동작까지 Harbor가 강제로 대답시키지는 않습니다.

1.7.3 업데이트 전의 일반 범위 변경 질문이나 반복 검토로 중단된 기록은 분석·대화·지시 버전을 보존합니다. 업데이트 후 **원래 대화 다시 열기 → 연결 확인 후 계속**으로 이어가면 기존 방향 선택 질문에 답할 필요 없이 AI끼리 다음 작업을 정합니다. 실제 고정 제약·사용자 정보·외부 허가 요청과 수동 일시정지는 유지합니다.

연구실에서 기존 Claude 대화를 다시 열 때도 같은 대화 ID로 자동 수신 채널을 요청합니다. 기존 대화의 모델·effort를 덮어쓰지 않으며 Claude CLI의 채널 허용·계정·조직 정책은 그대로 따릅니다. 연구실 밖의 일반 대화 재개는 기존 방식입니다.

참여자 이름을 누르면 원래 터미널로 이동하고, **두 터미널 함께 보기**로 나란히 볼 수 있습니다. **토론·실험·결과 보기**에서는 실제 제출 의견, 질문·답장, 작업 기록, 산출물과 결과를 확인합니다. 완료·일시정지·사용자 확인 요청은 알림으로 표시됩니다. **문서로 새 창에서 보기**는 중간 또는 최종 결과를 Markdown 창으로 엽니다.

코드 공동 작업에서 **주 대화는 선택한 현재 작업 폴더에서 수정**하고, 새 추가 AI는 깨끗한 Git 프로젝트에서 별도 worktree와 브랜치를 사용합니다. 시작 화면에 이 작업 범위를 표시합니다. 같은 작업 폴더의 기존 세션 두 개는 코드 과제에 사용할 수 없습니다. 결과에는 실제 변경 위치·브랜치·검증 내용을 기록하며 다른 참여자의 변경을 자동 병합하지 않습니다. 구버전에서 생성한 전용 두 세션 연구실은 기존 독립 worktree 구조를 유지합니다.

실험 기록은 **AI가 보고한 실행 결과**입니다. 상대는 등록된 산출물의 실제 내용을 읽고 검토할 수 있지만 파일 읽기만으로 테스트 실행이 입증되는 것은 아닙니다. 네이티브 실행·파일·보안 승인은 기존 CLI 규칙을 따릅니다. 사용자가 시작한 현재 연구실의 기록 교환과 참여자 사이의 질문·답장만 과제 권한으로 처리합니다.

**일시정지**는 다음 배정 전달을 멈춥니다. 이미 전달된 작업과 실행 중인 실험을 강제로 종료하지 않으며 필요한 경우 해당 터미널에서 멈추세요. **배정 알림**은 미제출된 현재 배정을 다시 알리는 기능입니다. 추가 지시를 보내면 기존 중간 결과를 보존하고 변경된 조건으로 다시 판단합니다.

1.7 이전의 일반 질문 때문에 멈춘 연구실은 업데이트 후 분석과 질문을 보존한 일시정지로 복구합니다. **원래 대화 다시 열기 → 연결 확인 후 계속**으로 이어가면 이미 제출한 분석부터 AI끼리 검토합니다. 사용자 결정 요청이 남아 있으면 먼저 원래 대화의 연결을 확인하고 답변하세요. 업데이트를 위해 실제 실행 중 앱은 작업을 저장하고 완전히 종료한 뒤 다시 열어야 합니다.

새로고침은 현재 과제와 터미널을 유지합니다. 준비 중 연구실은 재시작 후에도 준비 상태와 계획을 복구하며 **원래 대화 다시 열기 → 연결 확인**으로 주 대화를 잇습니다. 준비 중 연구실을 삭제해도 선택한 터미널과 원래 대화 기록은 삭제하지 않습니다. 공동 작업 중 앱을 완전히 종료하면 로컬·일반 SSH의 전용 프로세스는 종료되고, 유지 SSH의 서버 프로세스는 분리되어 계속 실행됩니다. 과제 기록은 일시정지로 복구됩니다. 유지 SSH는 자동 재연결된 원래 터미널을 확인하고, 종료된 세션은 **원래 대화 다시 열기 → 연결 확인 후 계속**으로 각 참여자의 원래 서버와 네이티브 대화 ID에 재연결합니다. 다른 서버·대화로 바뀐 터미널에 과제를 자동으로 옮기지 않습니다. 과제 기록과 내보낸 문서는 Harbor 데이터 폴더의 `research.json`, `research-results`에 저장됩니다. 새 로컬 작업 폴더는 데이터 폴더의 `research-workspaces`, 새 SSH 작업 폴더는 해당 서버의 `~/.codex/harbor/research-workspaces`에 만들어집니다. 등록된 산출물은 작성한 참여자의 서버에서 읽습니다.

1.3에서 Codex 0.162.0·Claude Code 2.1.295의 낮은 effort로 실제 로컬 분석·검토·최종 결과 흐름을 확인했습니다. 1.5의 대화 준비·계획 저장·명시적 시작·맥락 공유·원격 서버 선택은 격리된 합성 대화와 인증된 MCP 요청으로 검증했습니다. 이번 검증에서 실제 사용자 SSH 서버는 실행하지 않았습니다. 이 컴퓨터의 Codex Windows 샌드박스에는 `helper_unknown_error: setup refresh had errors`가 발생했으므로 Codex 명령 실행 검증과 실제 파일·산출물 읽기를 구분합니다. 해당 오류를 Harbor가 실행 성공으로 처리하거나 보안 설정을 끄지 않습니다.

1.7의 자동 질문과 사용자 결정 분리는 격리된 로컬 기록·인증된 양측 MCP 요청·브라우저 UI로 검증했습니다. 실제 모델의 새 추론이나 사용자 서버 실험은 실행하지 않았으므로 자연어 토론 품질까지 보장하는 검증은 아닙니다.

## AI에게 새 연구실 맡기기

Harbor 터미널에서 실행한 Codex 또는 Claude에게 관리자 역할을 맡길 수 있습니다. 예를 들어 다음과 같이 말합니다.

> 너는 관리자야. 이 컴퓨터의 현재 프로젝트에서 새 Claude와 새 Codex를 띄워 두 설계안을 토론하게 해줘. 서로의 근거를 검토하고, 최종 추천안과 남은 불확실성까지 정리해줘. 테스트이므로 두 참여자의 effort는 지원하는 가장 낮은 값으로 해줘. 진행 상황을 확인하고 결과를 가져와.

관리자 대화는 그대로 두고 **별도의 새 Claude·Codex 터미널 두 개**가 생깁니다. **연구실** 탭에서 목표·기준, 관리자 대화, 참여자 연결·진행·결과를 볼 수 있습니다. 기존 터미널을 임의로 재사용하거나 재시작하지 않습니다. 서버가 다르면 등록된 서버 이름과 해당 프로젝트 경로를 함께 지정하세요. SSH는 일반 연결이 기본이며 tmux를 원할 때만 명시하세요. 대상 서버에 두 CLI가 설치·로그인되어 있어야 합니다.

관리자는 Harbor 도구로 서버를 확인하고 연구실을 시작하며, 실제 과제 수신·보고를 조회하고 추가 지시·일시정지·종료를 할 수 있습니다. **일시정지**는 새 과제 전달만 멈춥니다. **종료**는 해당 연구실에서 새로 만든 두 터미널의 작업도 종료하고 연구 기록은 보존합니다. 다른 대화로 바뀐 터미널이나 종료를 확인할 수 없는 서버는 실패 내용을 반환합니다.

두 참여자는 기존 연구실의 독립 분석 → 상호 검토 → 필요 작업 → 결과 정리 → 최종 검토 과정을 따릅니다. 관리자도 참가자의 판단을 읽고 사용자에게 설명할 수 있지만, 실제 테스트를 확인하지 않고 결과를 검증했다고 단정하면 안 됩니다. 진행 조회는 한 번에 최대 25초까지 기다릴 수 있으며, 시간 초과는 작업 완료를 뜻하지 않습니다. 관리자 AI의 대화 턴이 끝난 뒤 자동으로 다시 발언하는 기능은 포함하지 않습니다. 이후에는 관리자에게 진행·결과 확인을 요청하거나 연구실 탭을 봅니다.

기존 대화에서 논의한 배경이 자동으로 전부 복제되지는 않습니다. 관리자가 목표·완료 기준·배경·고정 제약을 정리하여 두 참여자에게 전달합니다. 로그인·CLI 보안 승인, 사용자만 알 수 있는 정보나 새 외부 작업 허가는 관리자 AI가 대신 처리하지 않습니다. 업데이트 후 새 도구가 보이지 않으면 해당 CLI의 MCP 도구 목록을 새로 연결하거나 대화를 저장한 뒤 재개하세요.

## 서버 목록에서 터미널 종료하기

일반 **서버** 탭에서도 터미널 이름 오른쪽 **X**를 누르고 **터미널 종료**를 선택하면 해당 세션을 종료합니다. 로컬·SSH 모두 지원하고 현재 선택한 세션이나 별도 창에 떠 있는 세션도 목록에서 종료할 수 있습니다. 선택 버튼과 종료 버튼은 분리되어 있어 X를 누르면 다른 터미널로 이동하지 않습니다. 해당 셸과 실행 중 프로그램은 종료되지만 Codex·Claude가 저장한 대화와 프로젝트 파일은 유지됩니다. 상단 터미널 탭의 X도 같은 처리를 사용합니다.

## 기존 연구실 기록 정리하기

연구실 목록에서 각 이름 옆 **휴지통**을 누르면 해당 기록을 삭제합니다. 상단의 **휴지통(연구실 기록 모두 삭제)**은 현재 목록을 한 번에 정리합니다. 확인 창에서 대상 이름을 확인하고 **기록 삭제** 또는 **전체 기록 삭제**를 누르세요. 취소하면 유지됩니다. 확인 창을 연 뒤 새로 생긴 연구실은 삭제 대상에 포함되지 않습니다.

준비·진행·일시정지·완료 기록을 삭제할 수 있으며 선택한 연구실의 계획·토론·실험 내역과 관련 Harbor 과제·질문·답장 메시지가 함께 삭제됩니다. 새 배정은 중단하고 삭제한 기록은 복구할 수 없습니다. **열려 있는 터미널, Codex·Claude 자체 대화 기록, 프로젝트 파일·worktree와 내보낸 결과 문서는 보존**합니다. 원래 대화를 다시 선택하여 새 연구실을 만들 수 있습니다.

이미 AI에게 전달된 과제와 실행 중 명령은 기록 삭제로 자동 종료되지 않습니다. 필요하면 해당 터미널에서 중단하세요. **실행 중으로 등록된 작업의 터미널이 열려 있으면 삭제를 보류**합니다. 작업 결과를 등록하거나 작업을 중단하고 해당 터미널을 닫은 뒤 정리할 수 있습니다. 여러 기록을 삭제할 때 하나라도 이런 작업이 있으면 전체 삭제를 보류합니다. 터미널이 이미 종료된 오래된 실험 기록은 삭제할 수 있습니다.

## 새 버전 받기

**반복해서 클론하지 않습니다.** 처음 받은 Harbor 폴더에서 다음 순서로 진행합니다.

1. 터미널에서 하던 작업과 파일을 저장합니다.
2. Harbor를 완전히 종료합니다. 마지막 앱 창을 닫으면 로컬·일반 SSH 터미널 프로세스도 종료됩니다. **서버에서 세션 유지**인 SSH는 연결만 분리하며 업데이트 후 같은 실행 프로세스로 복구합니다. 유지 미지원 세션의 대화는 CLI 기록에서 이어갈 수 있지만 프로세스 자체가 유지되는 것은 아닙니다.
3. 아래 명령을 실행합니다.

```powershell
cd <처음 클론한 Harbor 폴더>
.\Update-Harbor.cmd
```

최신 main을 fast-forward로 받아 의존성을 다시 설치하고 빌드한 뒤 실행합니다. 자동 백그라운드 업데이트는 없으며 사용자가 명령을 실행해야 합니다. 창을 자동으로 열지 않으려면 ` .\Update-Harbor.cmd -NoLaunch`를 사용합니다.

`.data` 사용자 설정은 삭제하지 않습니다. 업데이트를 위해 `.data`나 CLI의 기록 폴더를 지우지 마세요. 중요한 설정은 앱 종료 후 별도로 백업하고 외부에 공개하지 마세요. SSH 자격 증명은 OS 계정에 묶여 다른 컴퓨터에서 다시 입력해야 할 수 있습니다.

## 문제가 생겼을 때

Harbor 창에 **연결 프로세스가 종료되어 다시 시작하고 있습니다**가 나오면 앱이 소유한 백엔드의 종료를 감지한 상태입니다. 2분 안에 최대 세 번 자동 복구하며 실패하면 **연결 복구**로 다시 시도할 수 있습니다. 실행 중인 백엔드를 강제로 종료하지 않습니다. 서버에서 유지 중인 원격 세션은 다시 연결하지만, 이미 종료된 로컬·일반 SSH 프로세스는 대화 기록에서 재개해야 합니다. 이 안내는 SSH 연결만 끊긴 경우와 구분됩니다.

진단용 `.data/runtime-events.jsonl`에는 30초마다 메모리 수치와 프로세스 시작·정상 종료·처리되지 않은 오류의 종류를 기록합니다. `.data/desktop-events.jsonl`에는 실제 자식 프로세스 종료 코드와 복구 결과가 남습니다. 용량은 제한되며 대화·명령·주소·환경 변수·예외 원문은 기록하지 않습니다. 앱을 재시작하기 전 발생 시각과 이 기록을 확인하면 메모리 부족, 백엔드 종료, 화면 연결 문제를 구분하는 데 도움이 됩니다.

터미널의 **화면 연결 복구 중**은 Harbor 화면과 백엔드 사이의 연결 상태입니다. SSH 연결 상태 안내와 구분합니다. 1.10.6부터 연결 완료·화면 복원이 지연되거나 서버의 주기 응답이 끊기면 화면만 자동으로 다시 연결합니다. **화면 다시 연결**도 같은 서버 작업을 유지한 채 보기만 다시 구성합니다. 앱 전체를 종료하는 것과 달리 셸을 새로 실행하거나 명령을 입력하지 않습니다. 실제 서버·SSH 프로세스가 종료된 경우 이를 복원하는 기능은 아닙니다.

문제가 반복되면 발생 시각과 모든 창인지 특정 창인지 함께 알려주세요. 개인 데이터 폴더의 `view-connections.jsonl`은 화면 연결 단계·오류 코드를, `terminal-disconnects.jsonl`은 SSH 연결 원인을, `desktop-events.jsonl`은 창 응답 정지·화면/백엔드 프로세스 종료 코드를 기록합니다. 화면 연결 감시 전체는 백엔드도 1.10.6 이상일 때 동작합니다.

| 상황 | 조치 |
| --- | --- |
| 실행 중이라고 표시됨 | 이 설치 폴더에서 실행한 Harbor와 관련 개발 작업을 종료하고 재시도합니다. 업데이트 도구가 강제로 종료하지 않습니다. |
| local changes 오류 | `git status`로 직접 수정한 소스를 확인하고 별도 백업하거나 커밋합니다. 무작정 reset/clean하지 마세요. |
| fast-forward 실패 | 별도 개발 커밋으로 main과 갈라졌을 수 있습니다. 개발자에게 이력 정리를 요청합니다. |
| 다운로드/빌드 실패 | 오류를 확인하고 연결 문제 등을 해결한 뒤 `Setup-Harbor.cmd`를 다시 실행합니다. 사용자 데이터를 삭제하지 않습니다. |
| 실행만 해도 이전 화면이 나옴 | 완전 종료 후 다시 실행했는지 확인합니다. 새로고침만으로 백엔드나 데스크톱 런타임은 교체되지 않습니다. |
| 설치 버전과 실행 버전이 다르다는 안내 | 작업을 저장한 뒤 기존 Harbor에서 Ctrl+Q로 완전히 종료하고 고정 아이콘을 다시 누릅니다. 일부 창만 닫으면 이전 앱이 남을 수 있습니다. 독립 웹 서버를 실행했다면 해당 서버도 직접 종료해야 합니다. |
| ZIP으로 받았음 | Git 업데이트는 지원하지 않습니다. 새 ZIP은 별도 폴더에서 설치하거나 Git 클론 방식으로 전환합니다. |

## 버전 확인

```powershell
git log -1 --oneline
(Get-Content package.json -Raw | ConvertFrom-Json).version
```

이 값은 **받아 둔 소스 버전**입니다. 실행 중인 앱이 이전 프로세스라면 실제 실행 버전과 다를 수 있으므로 업데이트 후 재실행해야 합니다. 변경 사항은 [CHANGELOG](../CHANGELOG.md)를 확인하세요.

앱 왼쪽 Harbor 이름 옆에도 표시된 화면의 버전이 나옵니다. 앱을 시작하지 않고 선택된 설치본과 실행 중 서버를 비교하려면 다음 명령을 사용합니다. `compatible: false`이면 작업 저장 후 완전 종료·재실행이 필요합니다.

```powershell
.\Start-Harbor-Desktop.ps1 -CheckOnly
```
