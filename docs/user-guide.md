# Harbor 사용자 설치·실행·업데이트

## 처음 설치

Windows 10/11 x64, Windows PowerShell 5.1, Git, 인터넷 연결이 필요합니다.

```powershell
git clone https://github.com/kimjongjip/Harbor.git
cd Harbor
.\Setup-Harbor.cmd
```

Node.js와 Electron 등은 저장소 안에 자동 다운로드·설치하고 빌드합니다. 관리자 권한은 필요하지 않습니다. Codex·Claude는 사용할 컴퓨터/서버에 별도 설치하고 본인 계정으로 로그인해야 합니다.

설치가 끝나면 바탕화면에 **Harbor 아이콘**을 자동 생성합니다. 다음부터는 이 아이콘을 더블클릭하면 됩니다. OneDrive 등으로 바탕화면이 이동된 경우에도 Windows가 지정한 바탕화면에 만듭니다. Setup이나 Update를 다시 실행하면 기존 Harbor 바로가기의 경로도 갱신합니다. 설치 폴더를 옮겼다면 Setup을 다시 실행하세요.

`Start-Harbor.cmd`를 더블클릭하거나 ` .\Start-Harbor.cmd`를 실행해도 됩니다. `Setup-Harbor.cmd -NoLaunch`는 설치·빌드와 바로가기 생성까지 하고 앱은 열지 않습니다. 바탕화면 쓰기 권한 또는 Windows Script Host 정책 때문에 바로가기를 만들 수 없으면 경고를 표시하며 앱 설치는 유지합니다.

Claude 대화 기록의 제목은 세션 이름, 사용자 지정 이름, AI 생성 제목, 요약, 질문 순으로 읽습니다. 제목이 아직 없는 기록은 내부 명령 태그 대신 실제 질문을 표시하며 명령만 있는 기록은 `/review`처럼 읽을 수 있는 명령으로 표시합니다. 목록·검색·미리보기에 같은 제목을 사용합니다.

## PDF 열기와 하위 폴더에 업로드

터미널의 PDF 경로를 Ctrl+클릭하면 독립 미리보기 창에서 열립니다. 절대경로와 현재 작업 폴더 기준 상대경로를 지원하며 로컬·SSH 서버의 파일 모두 같은 방식으로 읽습니다. 파일 탐색기의 PDF도 클릭해 열 수 있습니다. PDF 창은 내장 뷰어로 페이지 이동·확대·텍스트 선택을 지원합니다.

로컬 파일을 탐색기의 하위 폴더 행 위에 놓으면 그 폴더에 업로드합니다. 대상 폴더가 강조되고 업로드할 경로가 표시됩니다. 왼쪽 트리의 닫힌 폴더에 잠시 머무르면 펼쳐져 더 깊은 하위 폴더를 선택할 수 있습니다. 빈 공간에 놓으면 현재 열린 폴더로 업로드합니다. 크게 보기 화면에서도 폴더 행에 놓을 수 있습니다. 기존 파일은 덮어쓰지 않으며 폴더 자체를 통째로 올릴 때는 압축 파일을 사용합니다.

## 왼쪽 패널 너비 조절

서버·파일·받은 요청 패널의 오른쪽 경계를 드래그하면 너비가 바뀝니다. 조절한 너비는 이 컴퓨터에 저장되어 패널을 접었다 펼치거나 새로고침해도 유지됩니다. 터미널 공간을 확보하도록 최소·최대 너비를 제한합니다.

경계를 두 번 클릭하면 해당 패널의 기본 너비로 돌아갑니다. 키보드로 경계에 초점을 맞춘 뒤 좌우 방향키로 조절할 수도 있습니다. Shift를 누르면 더 크게 조절하고 Home 또는 Enter로 기본 너비로 돌아갑니다.

## 인용하여 질문

터미널 답변에서 글을 드래그해 선택하고 `인용하여 질문`을 누르면 해당 터미널 아래에 작은 입력 패널이 열립니다. 선택한 내용은 `[#1 annotation]`처럼 표시됩니다. 다른 부분을 선택해 추가하면 새 번호가 붙습니다. 번호는 서버가 할당하므로 다른 창에서도 중복되지 않습니다.

번호를 누르면 선택한 원문과 출처를 확인하고 그 부분에 대한 질문·코멘트를 작성할 수 있습니다. 각 번호는 원문과 해당 코멘트를 함께 담는 첨부 항목입니다. 다른 부분을 추가하면 새 번호의 코멘트를 작성하며, 이전 번호를 누르면 기존 코멘트를 다시 확인·수정할 수 있습니다. 옆의 ×로 해당 참조를 삭제해도 나머지 번호의 내용은 유지됩니다. 한 번에 최대 8개를 붙일 수 있습니다.

`입력에 추가` 또는 Ctrl+Enter를 누르면 실제 CLI 입력칸에는 `[#1 annotation]` 같은 번호만 들어갑니다. 인용 원문과 그 번호에 작성한 질문·코멘트는 번호 안에 연결되어 있으며 입력칸에 풀어서 표시하지 않습니다. 터미널에서는 번호 뒤에 일반 질문을 계속 작성할 수도 있습니다. 자동으로 전송하지 않으며 터미널에서 Enter를 눌러 보냅니다.

선택한 본문과 해당 번호에 작성한 질문·코멘트는 Harbor가 보관하다가 CLI의 `UserPromptSubmit` 훅에서 별도 문맥으로 함께 전달합니다. 원문·코멘트·출처는 입력칸에 나타나지 않습니다. 선택한 원문과 서버·터미널·작업 폴더를 연결하고 앞뒤 글은 추가하지 않습니다. 해당 터미널과 대화에 속한 번호만 사용할 수 있습니다.

이는 VS Code 확장의 내부 구현과 동일하다는 뜻은 아닙니다. 공식 VS Code 확장 패키지에서도 선택문·주석·출처를 별도 문맥으로 직렬화하는 코드를 확인했지만, Harbor는 네이티브 CLI 훅을 사용하며 입력칸의 번호는 편집 가능한 텍스트입니다. Codex CLI 0.160.0에서 기본 연결을 검증했고, 0.160.1에서 번호만 보이는 입력 화면과 인용 원문·코멘트가 함께 전달되는 것을 검증했습니다. 훅 연결을 사용할 수 없을 때 본문을 대신 붙여 넣는 경로는 없습니다. 앱 업데이트는 실행 중인 Codex에 새 훅을 추가하지 않으므로 작업을 저장한 뒤 Harbor와 Codex를 다시 실행해야 합니다.

참조는 현재 실행 중인 Harbor에 보관됩니다. 삭제하거나 해당 터미널을 닫으면 더 이상 연결할 수 없습니다. 이미 전송한 선택문은 CLI 대화 문맥에 포함됩니다.

## 다른 세션에 질문·답장

1. 로컬 또는 SSH 터미널을 둘 이상 열고 각 터미널에서 `codex` 또는 `claude`를 실행합니다.
2. 터미널 이름 변경 버튼으로 `구현`, `리뷰`처럼 서로 다른 이름을 정합니다. 같은 이름이 여러 개면 AI가 대상을 다시 구분해야 합니다.
3. 구현 세션에 “리뷰 세션에 이 구조를 선택한 이유를 물어보고, 답을 반영해서 계속 진행해줘”라고 요청합니다. 도구 이름이나 내부 ID를 프롬프트에 적을 필요는 없습니다.
4. 왼쪽 **받은함 → 메시지**에서 요청·답장과 실제 전달 상태를 확인합니다. 세션 목록을 누르면 해당 터미널로 이동합니다.

Codex↔Codex, Codex↔Claude, Claude↔Claude가 같은 받은함을 사용합니다. 같은 서버와 서로 다른 SSH 서버에도 같은 이름 기반 도구를 사용합니다. 답변은 새 AI 대화를 만들어 추측하는 방식이 아니라 상대의 실행 중인 네이티브 대화에서 작성됩니다. AI가 도구를 실제로 호출해야 전달되며, 자동으로 도구를 선택하는 빈도까지 보장하지는 않습니다.

| 표시 | 의미 |
| --- | --- |
| 자동 수신 | Codex 네이티브 대기열 연결. 작업 중에는 현재 작업이 끝난 뒤 요청을 처리합니다. |
| 채널 수신 요청 | Claude 채널을 요청한 연결. Claude의 계정·조직 정책과 CLI가 실제로 허용해야 자동 수신됩니다. |
| 받은함 확인 필요 | 상대 CLI에 “받은 메시지 확인해줘”라고 요청합니다. |
| CLI 알림 전달 · AI 확인 대기 | CLI 전송 경로가 알림을 받았지만 AI가 읽었다는 증거는 아직 없습니다. |
| AI 확인 | 수신 AI가 인증된 메시지 도구로 실제 메시지를 읽었습니다. 작업 완료를 의미하지는 않습니다. |
| 답장 도착 | 해당 질문 ID에 연결된 실제 답장이 왔습니다. |
| 원래 대화 연결 대기 | 받는 터미널이 다른 대화로 바뀌었습니다. 이전 질문을 새 대화에 자동으로 넣지 않습니다. |

Codex 자동 수신은 CLI 0.160.1 이상의 실험적 app-server·네이티브 대기열을 사용합니다. 지원하지 않거나 연결에 실패하면 받은함 방식으로 남습니다. 실행 중인 터미널에 Enter나 명령을 자동으로 입력하지 않으므로 작성 중인 프롬프트는 유지합니다. 기존에 실행한 CLI에는 업데이트만으로 새 연결이 생기지 않으므로 작업을 저장하고 Harbor와 CLI를 다시 실행하세요.

Claude 자동 수신을 요청하려면 `claude --harbor-peers`를 실행합니다. Harbor는 이를 해당 실행의 `--dangerously-load-development-channels server:harbor`로 바꾸고 세션 전용 MCP 설정을 추가합니다. 이 플래그는 Claude 개발 채널 허용 목록을 위한 옵션이며 명령 실행 승인을 대신하지 않습니다. Claude의 채널 확인 안내는 CLI에서 처리합니다. `-p`/`--print` 실행에서는 자동 채널을 요청하지 않습니다. 전역 Claude 설정은 변경하지 않습니다. 채널을 사용할 수 없다는 안내가 나오면 일반 받은함 도구를 사용하세요.

관리형 SSH는 연결된 서버의 `python3`와 SSH TCP forwarding을 사용합니다. 일반 OpenSSH 대체 연결에서는 자동 메시지 연결을 제공하지 않습니다. Harbor를 종료하면 이 실행의 터미널과 전용 app-server도 종료됩니다. 메시지는 `.data/mailbox.json`에 보관되지만 종료한 네이티브 대화를 새 대화에 임의로 연결하지 않습니다.

현재 Codex의 SSH 자동 수신 helper는 Linux에서 지원합니다. 다른 원격 운영체제는 받은함 방식으로 돌아갑니다. 실제 네이티브 검증은 Windows의 Codex 0.160.1과 Claude 2.1.258에서 격리한 모의 모델로 수행했습니다. 실제 원격 서버·계정의 자동 채널 허용 여부와 자연어에서의 자율적인 도구 선택 품질까지 검증한 것은 아닙니다.

응답을 기다리는 도구는 최대 50초 뒤 대기 중인 질문 ID를 돌려줍니다. 이 경우 AI는 결과 조회 도구로 답장을 확인하거나, 자동 수신이 가능한 세션에서는 나중에 도착한 답장을 처리할 수 있습니다. 대기 중이라는 결과를 동의·완료로 간주하지 않습니다. 다른 AI의 메시지는 작업 문맥이며 사용자의 새 실행 승인으로 취급하지 않습니다.

## 새 버전 받기

**반복해서 클론하지 않습니다.** 처음 받은 Harbor 폴더에서 다음 순서로 진행합니다.

1. 터미널에서 하던 작업과 파일을 저장합니다.
2. Harbor를 완전히 종료합니다. 마지막 앱 창을 닫으면 앱이 시작한 터미널 프로세스도 종료됩니다. CLI가 저장한 대화는 이후 기록에서 이어갈 수 있지만 실행 중 프로세스 자체가 유지되는 것은 아닙니다.
3. 아래 명령을 실행합니다.

```powershell
cd <처음 클론한 Harbor 폴더>
.\Update-Harbor.cmd
```

최신 main을 fast-forward로 받아 의존성을 다시 설치하고 빌드한 뒤 실행합니다. 자동 백그라운드 업데이트는 없으며 사용자가 명령을 실행해야 합니다. 창을 자동으로 열지 않으려면 ` .\Update-Harbor.cmd -NoLaunch`를 사용합니다.

`.data` 사용자 설정은 삭제하지 않습니다. 업데이트를 위해 `.data`나 CLI의 기록 폴더를 지우지 마세요. 중요한 설정은 앱 종료 후 별도로 백업하고 외부에 공개하지 마세요. SSH 자격 증명은 OS 계정에 묶여 다른 컴퓨터에서 다시 입력해야 할 수 있습니다.

## 문제가 생겼을 때

| 상황 | 조치 |
| --- | --- |
| 실행 중이라고 표시됨 | 이 설치 폴더에서 실행한 Harbor와 관련 개발 작업을 종료하고 재시도합니다. 업데이트 도구가 강제로 종료하지 않습니다. |
| local changes 오류 | `git status`로 직접 수정한 소스를 확인하고 별도 백업하거나 커밋합니다. 무작정 reset/clean하지 마세요. |
| fast-forward 실패 | 별도 개발 커밋으로 main과 갈라졌을 수 있습니다. 개발자에게 이력 정리를 요청합니다. |
| 다운로드/빌드 실패 | 오류를 확인하고 연결 문제 등을 해결한 뒤 `Setup-Harbor.cmd`를 다시 실행합니다. 사용자 데이터를 삭제하지 않습니다. |
| 실행만 해도 이전 화면이 나옴 | 완전 종료 후 다시 실행했는지 확인합니다. 새로고침만으로 백엔드나 데스크톱 런타임은 교체되지 않습니다. |
| ZIP으로 받았음 | Git 업데이트는 지원하지 않습니다. 새 ZIP은 별도 폴더에서 설치하거나 Git 클론 방식으로 전환합니다. |

## 버전 확인

```powershell
git log -1 --oneline
(Get-Content package.json -Raw | ConvertFrom-Json).version
```

이 값은 **받아 둔 소스 버전**입니다. 실행 중인 앱이 이전 프로세스라면 실제 실행 버전과 다를 수 있으므로 업데이트 후 재실행해야 합니다. 변경 사항은 [CHANGELOG](../CHANGELOG.md)를 확인하세요.
