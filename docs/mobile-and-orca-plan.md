# Harbor Mobile과 Orca 참고 계획

기준: 2026-11-04. 개인용 아이폰 홈 화면 웹앱(PWA)을 먼저 제공한다. PC 터미널을 기본으로 유지하고 같은 실행 세션을 휴대폰에서 읽고 조작한다. 이 문서는 구현 상태와 후속 계획을 분리한다.

## 2026년 11월 5일 추가 제안 · PC IDE와 다른 기기에서 이어 쓰기

상태: 사용자 승인 후 1.13.0에 IDE·모바일 축소·다른 PC 연결과 Tailscale 설치/로그인 안내를 구현했다. [현재 사용법과 제한](desktop-ide-guide.md). 아래는 설계 배경이며 독립 실행 데몬·여러 호스트를 한 화면에 통합하는 후속 단계는 미구현이다. 현재 재연결은 구독 식별자로 이전 화면을 분리하고 스냅샷 완료 전 들어온 출력을 큐에 보관해 뒤에 전달한다. 오프셋별 로그 이어받기는 아직 제공하지 않는다. 원격 기기에는 새 세션 생성·종료 권한을 부여하지 않는다.

### 기기별 역할

| 화면 | 제공할 작업 | 분리할 작업 |
| --- | --- | --- |
| PC 터미널 보기 | 기존 세션·SSH·Codex/Claude·연구실·파일 작업 | 기존 기본 화면 유지 |
| PC IDE 보기 | 파일 트리, 편집기 탭·분할, 검색, 변경 비교, 문서 미리보기, 같은 터미널과 인용 | 별도 AI 대화를 생성하지 않고 실행 중인 세션에 연결 |
| iPhone | 열려 있는 세션 목록, 터미널 출력·스크롤·입력, 이미지/파일 첨부, 세션 안의 승인·질문, 완료 알림, 연결 설정 | 연구실 탭·관리, 서버 관리, 새 세션 생성, IDE 편집기 로드 제외 |
| 다른 데스크톱 | 등록한 Harbor 호스트에 연결해 같은 터미널을 보고 제어; 이후 IDE 보기 연결 | 연결한 PC에서 같은 CLI를 중복 실행하지 않음 |

모바일은 연구실 버튼만 숨기지 않는다. 현재 `MobileState`의 labs/결과/참여자 전송, 연구실 변경에 따른 broadcast, 관련 UI·import를 함께 제거한다. 받은함의 승인·질문은 해당 세션 안에서 처리하고 세션 목록에는 확인 필요 표시만 남긴다. 별도 대화 모드 대신 터미널 안의 이전 질문·답변 스크롤을 유지한다. 편집기와 연구실 코드는 모바일 JS 경로에서 참조하지 않도록 분리한다. 연구실 제거만으로 네트워크 지연 전체가 해결된다고 가정하지 않고 전송량·첫 화면·전환 시간을 비교한다.

### IDE 구현 선택

권장안은 Harbor PC 화면에 Monaco Editor를 추가하는 것이다. 파일 모델의 키에는 호스트와 절대경로를 함께 넣어 다른 서버의 동명 파일을 구분한다. 최초 범위는 열기·수정·저장, 찾기/바꾸기, 편집기 탭·분할, 변경 비교, 선택 범위 인용이다. 언어 서버·디버거·확장 호스트는 후속 범위다. 편집기는 IDE 보기를 선택할 때만 로드한다.

[Code OSS 소스](https://github.com/microsoft/vscode)는 MIT이고 Microsoft 배포판 VS Code는 별도 제품 라이선스·추가 구성을 가진다. [Monaco](https://github.com/microsoft/monaco-editor)는 VS Code에서 사용하는 편집기이지만 VS Code 확장이 그대로 실행되는 제품은 아니다. 확장 생태계까지 필요하면 Code OSS 기반 별도 통합이나 [code-server](https://github.com/coder/code-server)를 비교해야 한다. code-server도 확장 제공 경로와 호스트별 실행부가 필요하다. 현재 Harbor의 터미널·SSH·AI 연결을 보존하는 목표에는 Monaco가 변경 범위를 작게 잡을 수 있다는 판단이다.

### 공통 실행부와 기기 연결

항상 켜 둘 PC 한 대를 Harbor 호스트로 정한다. 이 PC의 실행부가 로컬 PTY·SSH 연결·AI 프로세스·출력 버퍼를 소유한다. 사무실 PC 화면, 집 PC 화면, iPhone은 같은 실행부에 인증하여 접속한다. 예를 들어 집 PC의 **다른 Harbor 연결**에서 호스트 주소를 등록하면 사무실에서 열어 둔 세션이 보이고, 그 세션을 선택하면 같은 프로세스에 이어 입력한다. 기존 Funnel/Serve 경로를 활용할 수 있지만 PC 전용 API 토큰을 외부에 그대로 노출하지 않는다.

- 기기 등록에는 세션 읽기·입력·승인·파일 읽기/쓰기·세션 생성/종료 권한을 구분한다. 모바일에는 필요한 기존 세션 권한만 부여한다.
- 같은 터미널을 여러 기기에서 볼 수 있지만 입력·PTY 크기 변경의 제어권은 한 기기에 둔다. 다른 기기는 **여기서 제어**로 넘겨받고, 각 기기의 선택 탭·분할·스크롤은 독립적으로 유지한다. 휴대폰은 PC PTY 크기를 바꾸지 않는다.
- 호스트·실행 세대·터미널·네이티브 대화 식별자를 검증하고 이벤트 순서 번호로 재접속 시 snapshot 이후 출력만 이어 받는다. 입력 요청 ID를 사용해 ACK 유실 후 같은 명령이 중복 실행되지 않도록 한다.
- 파일은 호스트에서 읽고 저장한다. AI 또는 다른 PC가 수정한 파일은 저장 시 버전/hash 충돌을 확인하고 비교 화면을 제공한다. 오래된 편집기 내용으로 무조건 덮어쓰지 않는다.
- 첫 단계에서는 호스트 PC의 Harbor가 켜져 있어야 한다. 화면 앱을 닫아도 유지하려면 별도 실행 데몬 단계가 필요하다. 호스트 PC 전원이 꺼져도 계속 실행되려면 실제 실행부를 상시 서버로 옮겨야 한다. tmux는 이 구조의 필수 조건이 아니며 기존 세션을 자동 변환하지 않는다.

### 구현 순서와 검증

1. **모바일 축소**: 연구실 UI·데이터 제거, 세션 안에서 승인 처리, 열린 세션 중심 탐색. 모바일 빌드에 IDE 코드가 없고 입력·첨부·과거 스크롤·푸시가 유지되는지 검증.
2. **다른 PC에서 같은 세션 연결**: 별도 기기 등록과 데스크톱 원격 터미널 보기부터 제공. 실제 프로세스가 하나인지, 양쪽에 같은 출력이 오는지, 제어권 전환·연결 해제·재접속이 정확한지 검증.
3. **PC IDE 보기**: 기존 파일 서비스를 이용한 Monaco 편집·diff·탭·분할과 세션 연결. 원격 파일 동시 수정·저장 충돌·큰 파일 제한·보기 전환 시 터미널 유지 검증.
4. **선택형 독립 실행부**: 호스트 UI 종료와 작업 수명을 분리하는 별도 릴리스. 신규/기존 세션 이행 방법을 먼저 결정하고 사용자 작업을 강제로 재시작하지 않음.

이 순서는 세션 공유 기반을 먼저 확정한 뒤 IDE 파일 기능도 같은 기반에 연결하기 위한 것이다. 실제 iPhone/Funnel 초기·재방문 성능 비교와 두 PC의 동시 제어 검증은 격리 브라우저 테스트와 별도 확인 항목이다.

## 변경 범위와 순서

기존 터미널·SSH·승인·첨부·연구실 서비스를 재사용한다. 모바일 화면, 인증된 모바일 전용 서버, 재접속·알림을 추가한다. PC UI와 세션 실행부 전체를 교체하지 않는다. 첫 버전은 현재 PC의 Harbor가 실행 중이어야 한다. 모바일 접속을 위해 tmux를 자동 적용하거나 사용자 서버에 프로그램을 설치하지 않는다.

| 단계 | 범위 | 완료 조건 |
| --- | --- | --- |
| 1 — 이번 구현 | 개인용 PWA, PC에서 기기 연결·해제, 서버별 세션, 터미널 출력·입력·키·첨부, 받은함 승인·질문, 연구실 현황, Web Push | 인증 전 데이터 차단, 폐기 즉시 차단, 같은 PTY 공유, 재접속 복구, 중복 입력 방지, 모바일 화면 검증 |
| 2 — 후속 | 화면과 독립된 세션 실행 데몬, 서버 실행 모드 | UI·접속 서버 재시작 후 동일 프로세스와 출력 복구, 종료와 연결 해제 구분, 종료 확인·재부팅 한계 표시 |
| 3 — 후속 | 집 PC·아이폰·사무실 PC의 공통 런타임, 여러 호스트 | 기기별 권한·입력 소유권·화면 크기 정책, 이벤트 이어받기, 중복 탭과 입력 방지 |
| 4 — 후속 | 연구실 관측·작업 관리 | 작업/시도/담당자 ID, 질문 수신자, 마지막 진행·정체 이유, 결과 파일·검증 증거·재시도 표시 |
| 5 — 후속 | 코드 검토·작업 공간·자동화 | 독립 worktree 비교, 줄 단위 주석, 체크포인트, 명시한 일정·범위의 예약 실행 |

단계 1의 코드·격리 검증과 실제 아이폰 검증은 별도로 기록한다. Safari 설치·실기기 키보드·사진 선택·백그라운드 복귀·잠금 화면 푸시는 사용자의 아이폰과 개인망 연결 후 확인해야 한다.

### 1.12.0 구현 상태

단계 1의 PWA 화면과 모바일 전용 인증 서버를 구현했다. PC 상단 휴대폰 설정, 일회용 등록·기기 폐기, 기존 세션 읽기/입력/특수키/첨부, 실제 요청 응답, 연구실 현황, 완료 답변 표·수식 보기, Web Push 구독·테스트를 포함한다. 첫 버전의 새 터미널 생성·전체 저장 기록·연구실 편집은 PC에서 한다. 터미널 조판을 휴대폰 화면에서 재설정하지 않고 별도 완료 답변 보기를 제공한다.

자동 검증은 합성 세션·개별 데이터 폴더·390px 브라우저에서 수행한다. 코드 검증과 실제 Apple Push 전달은 구분하며 사용자 서버나 현재 대화에는 테스트 입력을 보내지 않는다. 개인 Tailscale 설치/로그인과 아이폰 홈 화면 등록은 [사용 안내](mobile-guide.md)대로 진행한다. 단계 2~5는 아직 구현하지 않았다.

단계 1은 기존 코드를 대부분 유지하는 추가 작업이다. 단계 2는 세션 수명·프로세스 소유권·복원 저장을 바꾸는 큰 작업이며 별도 릴리스로 검증한다. 단계 3은 인증·여러 기기 간 충돌 정책까지 넓힌다. 단계 4~5는 이 기반 위에서 연구실과 코드 검토 UI를 확장한다.

## 모바일 연결 설계

- 기본 꺼짐. PC의 모바일 설정에서 개인 HTTPS 주소를 지정하고 켠다.
- PC 로컬 UI(기본 4317)와 별도로 모바일 전용 루프백 포트(기본 4318)를 사용한다. Tailscale Serve는 **4318만** 연결한다. 기존 bootstrap 토큰이나 서버 관리 API를 프록시하지 않는다.
- 짧은 수명의 1회 연결 링크를 PC에서 생성한다. 링크 비밀값은 URL fragment에 넣고 연결 즉시 주소에서 지운다. 등록 후 HttpOnly 쿠키로 인증한다. 서버에는 기기 토큰 해시만 저장한다.
- 요청 Origin·Host 검사, 등록 시도 제한, 기기 즉시 해제, 변경 요청 CSRF 검사, 응답 캐시 금지. 기기에는 개인 계정의 세션 제어 권한을 주며 다중 사용자 서비스로 설명하지 않는다.
- 휴대폰은 PC의 터미널 크기를 변경하지 않는다. 넓은 화면은 가로 스크롤하고 모바일 글자 크기를 조정한다. 새 연결에서 화면 스냅샷 뒤의 출력을 순서대로 전달한다.
- 입력은 사용자가 전송한 경우만 처리한다. 요청 ID로 중복을 막고 결과가 불분명한 입력은 자동 재전송하지 않는다. 백그라운드 복귀 시 다시 연결하고 초안은 기기 메모리에 유지한다.
- 첨부는 기존 세션별 임시 디렉터리에 업로드하고 경로를 초안에 넣는다. 이미지·파일만 올려도 Enter가 자동 전송되지 않는다.
- Push는 홈 화면 설치 후 사용자가 허용한 기기에만 보낸다. 잠금 화면에는 명령·답변 본문을 넣지 않는다. 구독 만료·실패를 처리하며 푸시 수신은 플랫폼·네트워크 상태에 따라 실기기 확인이 필요하다.

| 일정 기반 자동화 | 지정 호스트·작업·모델·완료 기준·실행 이력·취소를 갖춘 예약 작업 | 중간 |
| Design Mode | 페이지 요소의 DOM·스타일·캡처를 묶은 수정 요청 | 낮음 |
| 체크포인트·작업 복원 | 파일 버전 복원과 실행 프로세스 복원을 구분 | 중간 |
| CLI 제어·검색·상태 피드 | 기존 관리자 AI 도구와 연구실 UI의 공통 API 정리 | 중간 |

Orca의 모바일/원격 서버는 베타이며 협업 문서는 일부 버전의 패널 비활성화를 알린다. 기능 소개를 Harbor의 실증된 안정성으로 취급하지 않는다. 코드를 옮길 경우 MIT 저작권 고지를 보존하고 의존성·플랫폼 차이를 검토한다. 이번 구현은 기존 Harbor 서비스를 이용하며 Orca 소스를 복사하지 않는다.
