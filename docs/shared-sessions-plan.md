# Harbor 기기 간 공유 세션 계획

작성: 2026-10-05. 2026-11-05 현재, 1.13.0에 실행 중인 호스트의 공통 세션 목록·기기 등록·iPhone 화면·원격 PC 터미널/IDE·기기 간 입력권을 구현했다. 독립 실행 데몬·여러 호스트 통합은 후속 단계다. [현재 사용법](desktop-ide-guide.md). 아래 날짜별 문단은 당시 상태를 남긴 이력이다.

2026-10-26 보완: 1.8.5는 새 SSH 터미널의 자동 tmux 적용을 철회했다. 현재 기본은 직접 SSH이며 기존 유지 세션만 복구·종료 호환을 제공한다. 아래 1.8.0 설명은 이전 구현의 이력이다.

2026-10-24 보완: Harbor 1.8.0은 아래의 원격 프로세스 유지 부분을 단일 설치에 구현했다. 새 관리형 SSH 터미널은 tmux가 있으면 앱 재시작·연결 단절 뒤 같은 프로세스와 브리지에 다시 붙는다. 중앙 서버·기기 인증·공통 목록·아이폰 화면·기기 간 입력권은 아직 구현하지 않았다. 현재 지원 범위는 [장시간 SSH 작업 유지](user-guide.md#장시간-ssh-작업-유지)를 따른다.

## 목표

연구실 PC, 집 PC, 아이폰에서 같은 서버 목록과 실행 중인 터미널에 접속한다. 연구실 PC의 원격 데스크톱을 켤 필요 없이 작업을 이어간다. 터미널에서 Codex를 실행하는 현재 사용 방식을 유지한다.

## 구성

- 항상 켜져 있는 Harbor 중앙 서버: 사용자 인증, 서버 목록, 공통 세션 ID, 요청·승인, 파일 접근 및 접속 상태 관리.
- 실제 작업 서버: Linux 원격 서버 등의 셸과 Codex 프로세스를 유지.
- PC Harbor와 아이폰 웹 화면: 중앙 서버에 접속하는 클라이언트. 클라이언트 창을 닫아도 공유 세션은 종료하지 않음.
- 로컬 모드의 기존 종료 정책과 중앙 서버 모드를 명확히 분리. 문서 창 닫기와 터미널 종료도 별개 동작으로 유지.

## 세션 유지 방식

tmux는 필수가 아니다. 대안은 각 작업 서버에 전용 PTY 상주 프로그램을 설치하는 것이다. 첫 구현에서는 Linux 작업 서버에서 tmux를 내부적으로 사용하는 방식을 우선 검토한다. 사용자가 tmux 단축키를 익힐 필요 없이 Harbor가 생성·재접속·명시적 종료를 관리한다.

tmux는 중앙 서버와 SSH 연결이 끊겼을 때 작업을 유지하는 데 사용한다. 작업 서버 자체의 재부팅까지 실행 중인 프로세스를 보존하지는 못한다. Windows 로컬 세션은 별도 상주 프로세스 방식이 필요하며 Linux와 같은 방식으로 지원한다고 가정하지 않는다.

## 실시간 동기화

- 공통 세션 ID로 목록과 실행 상태를 동기화하고, WebSocket으로 실제 터미널 입력·출력을 전달.
- 재접속 시 화면 스냅샷과 이후 출력의 순서를 보장하고 중복 입력 재전송을 방지.
- 한 시점에 한 기기가 입력 및 터미널 크기를 소유하도록 하고, 다른 기기는 관찰하거나 입력권을 넘겨받음. 여러 화면의 resize 경쟁 방지.
- 이미 터미널에 전달한 입력과 보조 입력창의 미전송 초안을 구분. 미전송 초안은 필요 시 별도 동기화하며 충돌 처리를 명시.
- 세션 로그·승인 요청의 접근 권한은 중앙 서버에서 검사.

## 아이폰

Safari 웹 화면과 홈 화면에 추가 가능한 웹 앱을 우선 구현한다. 세션 단일 화면, 한글 입력용 보조 입력창, Esc/Tab/Ctrl+C/방향키, 사진 첨부를 제공한다. 보조 입력은 기존 터미널에 전달하며 별도 AI 대화를 생성하지 않는다.

화면 잠금이나 백그라운드 전환 시 연결이 계속 유지된다고 가정하지 않는다. 서버는 작업을 계속하고, 다시 열면 최신 화면으로 복구한다. 읽기 쉬운 구조화 대화 보기는 추후 공식 Codex 연동 기능을 검증한 뒤 별도 설계한다.

## 접속과 보안

초기에는 Tailscale 같은 비공개 네트워크를 검토한다. 외부 접속용 인증·TLS·기기 접근 제어를 갖추고, 현재 로컬 bootstrap 인증 토큰 반환 방식을 그대로 인터넷에 노출하지 않는다. SSH 자격 증명은 서버에서 관리하고 클라이언트에 전달하지 않는다.

## 구현 순서와 완료 조건

1. 로컬 모드와 중앙 서버 모드를 분리하고 명시적 인증 및 서비스 실행 구성 추가.
2. Linux 작업 서버에 세션 유지 계층 연결. 연결 단절 후 같은 프로세스 재접속 확인.
3. 기기 간 목록·출력 동기화와 입력권/크기 소유권 구현. 두 기기 동시 접속 시 입력 혼합·화면 손상 없는지 확인.
4. 아이폰 화면·한글 입력·사진 첨부·재연결 구현. 실제 iPhone Safari에서 확인.
5. 선택적 초안 동기화, 요청 알림, 구조화 대화 보기 확장.

현재 사용자의 실행 중인 세션은 자동 이관하거나 종료하지 않는다. 중앙 서버 위치와 운영 방식은 실제 도입 시 결정한다.

## 답변 조판과 장기 연결

[답변 표시와 장기 세션 개선 계획](readability-and-session-plan.md)의 연결 종료 사유 기록, 원격 프로세스 유지, 훅·MCP 연결 복구를 함께 따른다. tmux를 적용할 때 Claude의 이미지 UI가 같은 방식으로 작동한다고 가정하지 않는다. 로컬 Windows 화면과 원격 Linux 프로세스 수명, 이미지 표시 및 텍스트 선택을 함께 검증한다.
