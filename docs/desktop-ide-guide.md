# PC IDE와 다른 기기에서 이어 쓰기 · 1.18

## 상단 연결 아이콘에서 준비하기

호스트는 지금 터미널을 실행하는 PC다. 호스트 Harbor의 상단 휴대폰 아이콘을 누르면 **휴대폰 · 다른 PC 연결**이 열린다.

1. **Tailscale 설치**를 누른다. Windows에서는 공식 winget 패키지의 설치 프로그램을 실행한다. Windows 확인 창은 직접 승인한다. winget이 없거나 다른 운영체제이면 공식 설치 페이지를 연다.
2. **로그인하기**를 누른다. Tailscale 공식 브라우저 인증을 완료한다. 이미 로그인·연결되어 있으면 계정을 바꾸거나 재로그인을 요구하지 않는다. 인증 창이 자동으로 열리지 않으면 **Tailscale 로그인 계속**을 누른다.
3. 주소가 자동 채워지면 **VPN 없이 연결 · Tailscale Funnel** 또는 **VPN으로 연결 · Tailscale Serve**를 고르고 **저장하고 연결 설정**을 누른다. Tailscale에서 추가 허용을 요구하면 표시되는 공식 링크에서 완료하고 다시 누른다.
4. 휴대폰은 **휴대폰 연결 링크 만들기**, 다른 PC는 **PC 연결 링크 만들기**로 등록한다. 10분 안에 한 기기에만 쓸 수 있고 새 링크를 만들면 이전 미사용 링크가 취소된다.

설치와 로그인은 버튼을 누를 때만 시작한다. Harbor 설치 스크립트가 모든 사용자의 Tailscale을 임의 설치·로그인시키지는 않는다. 계정 비밀번호는 Harbor에 입력하지 않는다. 다른 사용자가 Harbor를 설치하면 자기 PC에서 자기 계정으로 같은 과정을 진행한다. 본인의 호스트를 공유하려는 경우에는 등록 링크를 받은 기기가 열린 세션을 제어할 수 있음을 전제로 링크를 전달한다.

Funnel은 접속하는 휴대폰·PC에 VPN을 요구하지 않는다. Serve는 해당 개인망에 접근 가능한 Tailscale 연결이 필요하다. 호스트 PC의 Harbor와 Tailscale은 실행 상태로 둔다. [공식 Windows 설치](https://tailscale.com/docs/install/windows), [Tailscale CLI](https://tailscale.com/docs/reference/tailscale-cli).

## 다른 PC에서 같은 세션 사용

다른 PC의 Harbor 상단 **다른 Harbor 연결**을 누르고 PC 연결 링크를 붙여 넣는다. 또는 그 PC의 브라우저에서 링크를 연다. 이름을 정해 등록하면 호스트에서 열어 둔 세션이 보인다. 터미널 보기에서는 같은 프로세스의 출력과 입력을 공유한다. IDE AI 패널에서는 별도 새 대화와 기록 재개도 가능하다. 서버 관리·새 터미널 생성·연구실 관리·터미널 종료는 호스트 PC에서 한다.

여러 기기에서 볼 수 있지만 입력 제어권은 하나다. 보기만 하면 제어권을 가져가지 않는다. 입력을 처음 보내면 빈 제어권을 취득하고, 다른 기기가 제어 중이면 **여기서 제어**를 눌러 인계받는다. 호스트 PC에도 다른 기기의 제어 상태와 같은 버튼이 표시된다. 휴대폰은 터미널 크기를 바꾸지 않는다. 원격 PC는 제어 중일 때만 작업 화면에 맞게 터미널 크기를 바꾼다. 연결이 끊긴 기기의 제어권은 최대 30초 후 만료된다.

등록된 기기는 호스트 연결 설정에서 **연결 해제**로 폐기할 수 있다. 등록 기기의 인증 쿠키·개인 설정은 Git에 들어가지 않는다. 서버 관리 토큰이나 SSH 비밀번호를 원격 화면에 전달하지 않는다.

## PC IDE 보기

기본은 기존 터미널이다. 호스트 PC에서 상단 **IDE**를 선택하면 파일 탐색기·편집기가 왼쪽에 열리고, 사용하던 터미널이 그대로 오른쪽으로 이동한다. 작성 중인 프롬프트·작업 출력·실행 승인·Mods를 같은 입력창에서 사용한다. 상단에서 서버와 세션을 고르고, AI 채팅 패널 버튼으로 오른쪽 영역을 열거나 접는다. 패널 경계선을 드래그해 크기를 조절한다. 터미널 보기로 돌아가면 기존 분할 배치가 복원된다.

별도 **새 AI 대화 열기**를 선택하면 SDK 대화 패널로 전환하고, 필요하면 아래 터미널을 열어 함께 사용한다. **현재 터미널로 돌아가기**는 원래 화면을 복원하며 별도 새 대화 초안을 보존한다. 다른 PC 연결의 IDE는 아래 터미널과 독립 AI 패널 구성을 사용한다.

- 선택한 서버 계정의 실제 홈 폴더에서 시작한다. 원격 Linux에서는 보통 `/home/<계정>`이며 홈이 다른 위치라면 서버가 알려주는 경로를 사용한다. 터미널의 `cd`와 IDE 탐색 위치는 분리한다. 탭, 편집기 분할, 찾기·바꾸기, Ctrl+S 저장을 지원한다.
- 왼쪽 파일 탐색기의 오른쪽 경계 전체를 드래그해 너비를 조절한다. 기기별로 너비를 기억하며 터미널 보기의 사이드바 설정과 구분한다. 두 번 클릭하면 기본 너비로 돌아가고, 경계에 포커스 후 좌우 방향키로도 조절한다. 좁은 창에서는 편집 공간을 남기고 창을 다시 넓히면 선택한 너비를 복원한다.
- UTF-8과 BOM이 있는 UTF-16LE/BE를 자동으로 읽는다. 다른 인코딩의 한글 문서는 **한글 Windows (CP949)로 열기**를 선택한다. 저장 시 원래 인코딩과 BOM을 유지하고, 해당 인코딩으로 표현할 수 없는 문자는 원본을 덮어쓰지 않고 알린다. 상태 표시줄에서 현재 인코딩을 확인한다.
- 다른 AI·PC가 같은 파일을 바꾸면 바로 덮어쓰지 않고 충돌을 표시한다. 비교 화면에서 서버 내용과 편집본을 확인한 뒤 다시 저장한다.
- Markdown 파일은 기본 **읽기** 화면으로 연다. **원문 / 나란히 보기**로 편집하고 목차, Ctrl+휠 확대, 표·수식·Mermaid를 이용한다. 저장 전 초안도 읽기 화면에 반영된다. 호스트 IDE의 이미지·문서 링크는 현재 문서 폴더 기준이다. 다른 PC 연결의 Markdown은 텍스트·표·수식·Mermaid·문서 링크를 지원하며 이미지는 설명으로 표시한다.
- 선택한 코드에서 **인용**을 누르면 현재 터미널의 인용 창이 열린다. 질문을 적고 직접 전송하면 경로·줄 범위·원문·저장 전 여부를 함께 전달한다. 별도 새 AI 대화에서는 입력창의 첨부 표시로 들어간다. 인용을 여는 것만으로 전송하지 않는다.
- PDF와 PNG·JPG/JPEG·GIF·WebP·BMP·AVIF·SVG·ICO는 파일 크기와 관계없이 먼저 미리보기로 분류한다. 호스트 PC IDE에서 클릭하면 미리보기 창을 바로 열며, PDF·이미지 내용 편집은 제공하지 않는다. 2MiB 제한은 텍스트 편집에만 적용한다. 이미지의 이전 20MiB 제한은 제거했으며 로컬·SSH 파일을 스트리밍하고 PDF의 부분 읽기를 지원한다. 홈 폴더 밖으로 나가는 경로나 심볼릭 링크는 허용하지 않는다. 네이티브 AI 세션이 바뀌면 오래된 편집본은 자동 저장하지 않으며, 같은 세션의 `cd`는 저장 바인딩을 무효화하지 않는다.

### 오른쪽 AI 대화

아래 설명은 명시적으로 선택한 **새 AI 대화**와 다른 PC 연결의 독립 AI 패널에 해당한다. 호스트 PC에서 사용하던 터미널을 IDE로 옮기는 기본 동작에는 별도 입력 채널이 필요하지 않다.

열린 AI가 없는 경우 기본은 **새 대화**다. 위에서 **Codex / Claude**를 고르고 바로 질문을 보낸다. 아래 터미널에서 AI를 먼저 실행할 필요가 없다. 첫 전송 때 선택한 서버의 로그인된 CLI를 이용해 대화를 만들며, 계정 기본 모델과 홈 폴더를 사용한다. 작업 폴더 버튼에서 프로젝트 경로와 모델을 지정할 수 있다. 열린 파일이 있다고 작업 폴더를 임의 변경하지 않으므로 프로젝트 작업 전 경로를 확인한다.

위쪽 **대화 기록**에서 선택한 서버·AI의 이전 대화를 검색하고 이어간다. **새 대화** 버튼으로 새로운 주제로 시작한다. 이전 메시지는 **이전 대화 더 보기**로 불러온다. 같은 기록이 CLI에서 이미 열려 있으면 그 프로세스를 종료하지 않고 연결해 표시한다. 선택한 터미널에서 AI가 실행 중이면 처음 IDE를 열 때 작성 중인 초안이 없는 경우 자동 연결하며, **현재 터미널 대화**로도 연결할 수 있다. 명시적으로 새 대화를 고르거나 작성한 초안은 자동 연결이 덮어쓰지 않는다.

연결된 Codex는 기존 입력 대기열로 전송한다. IDE 사용자 입력을 지원하는 채널이 활성화된 Claude도 같은 프로세스에 메시지를 전달한다. 이전 버전 채널이나 일반 훅만 연결된 Claude는 대화 읽기를 제공하며 **터미널에서 입력**으로 원래 창을 열어 계속한다. 작업 중 기록은 주기적으로 갱신되며 아직 저장되지 않은 토큰·모든 도구 출력은 원본 터미널에서 확인한다. 기존 CLI의 실행 승인·중단도 같은 터미널에서 처리한다. 기존 프로세스를 새 SDK 엔진으로 복제하지 않는다.

IDE에서 만든 새 대화의 메시지는 Codex app-server와 Claude Agent SDK를 통해 직접 전달한다. 답변·도구 실행·질문·승인은 오른쪽에 표시하며 **작업 중단**으로 응답을 멈출 수 있다. CLI에 작성 중인 문장과 합치거나 터미널에 Enter를 보내지 않는다. 선택한 서버에 해당 CLI가 설치·로그인되어 있어야 한다. 별도의 API 키를 Harbor에 입력하는 방식은 아니다.

작성 중인 문장은 서버·제공자·대화별로 분리한다. 답변을 기다리는 동안 다른 대화를 볼 수 있고, 늦게 도착한 응답은 원래 대화에만 적용한다. 전송 결과가 불명확하면 자동으로 반복하지 않으며 같은 요청 번호로 재확인한다. Harbor 재시작 후에는 네이티브 대화 기록에서 재개한다. 모바일에는 IDE 채팅을 추가하지 않는다.

### VS Code 확장을 사용할 수 있나?

현재 Harbor는 Monaco 편집기를 사용하며 VS Code 확장 호스트는 포함하지 않는다. `.vsix`를 설치하거나 Microsoft Marketplace 확장을 바로 실행하는 기능은 없다. [Monaco 공식 FAQ](https://github.com/microsoft/monaco-editor#faq)에서도 일반 VS Code 확장은 Monaco에서 실행되지 않는다고 설명한다. [Codex 공식 확장](https://learn.chatgpt.com/docs/codex/ide)과 [Claude Code 공식 확장](https://code.claude.com/docs/en/vs-code)은 호환 IDE에 설치하는 제품이다. Harbor 오른쪽 대화 패널은 네이티브 AI 런타임의 구조화된 연결을 사용하는 Harbor UI다.

실제 확장 호환성을 추가하려면 Code OSS 등 전체 작업 공간과 확장 실행 프로세스, 원격 파일 시스템, 로그인·권한·배포 경로를 통합해야 한다. 후속 설계에서는 Windows/SSH별 확장 호스트 위치와 공식 확장의 설치·지원 조건을 검증하고, 기존 Harbor 세션·기기 인증과 연결하는 단계를 따로 다룬다. 모바일에서는 편집기나 확장 호스트 코드를 내려받지 않는다.

## 유지 범위

이 버전은 실행 중인 호스트에 접속하는 방식이다. 원격 연결 창을 닫아도 호스트 작업은 계속되지만, 호스트 Harbor를 종료하거나 PC를 끄면 일반 로컬·SSH 세션을 계속 유지하는 독립 데몬은 아직 없다. 기존 tmux 선택은 그대로이며 공유 기능이 tmux를 강제로 켜지 않는다. 새로고침 시 화면 스냅샷 다음 출력을 순서대로 복원하고, 전송 결과가 불명확한 입력은 자동 반복하지 않는다.
